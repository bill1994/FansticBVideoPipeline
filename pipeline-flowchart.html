一、总览流程图

中间为确定性主管线（00-input → 05-render）；左侧为人类 / 模型侧（素材投放、人工审批、意图层编辑）；右侧为辅助工具与规划中的创作期生成。红色虚线 = 人工闸与返修回路；紫色虚线 = 计划改动（提案 2026-10-22，ACCEPTED，尚未落地）。

读图说明：① 琥珀色双箭头 —— 03 首跑生成 motionboard.json 意图底稿（虚线，保底路径）→ 模型 / 人工编辑 → 回读烘焙（实线）；管线除首跑外对该文件只读。首选路径是 LLM 语义判定 pacing 后同批落 motionboard（M-3 用户裁决 2026-10-23：语义优先于复现；规则生成器降级为兜底先验，见 03 节点明细）。② 红色长虚线 —— 人类审批 confirmed.json 的两条消费路径：对齐门控放行（进 01 后由 storyboard 查证）与 fullscreen 启动闸（进 05-render）。③ 紫色虚线框 = 计划改动（提案 2026-10-22 ACCEPTED，尚未落地）；当前 cli.ts 无 review 命令，must_review 仅是警告队列（见第五节断点表）。

回流回路

回路 1（返修）： 04-validate 报 error ⇒ 回 03-storyboard 改 motionboard.json ⇒ 重跑 storyboard → validate → render。阶段目录为不可变快照：改上游（01/02）代码须 --force 才重跑；下游（03/04/05）每次重算。
回路 2（降级放行）： 01-align 门控不过 ⇒ 人工写 06-review/confirmed.json（stage:"alignment"）⇒ storyboard 回填 confirmedBy/At 进 meta（降级到 cue 级时 meta.anchorMode 必须标 'cue'）。fullscreen（D3）⇒ 写 stage:"render" + acknowledgedFullscreen。
回路 3（规划 · P1-a）： validate ok=true ⇒ review 启动 Studio 预览 ⇒ 不满意可回 03 改 motionboard.json，或走 P1-b 生成新 MotionSpec 定稿入库；确认后写 confirmed.json 已审核条目清单 ⇒ render 启动闸校验 must_review 全覆盖才放行。

四、计划中的改动（已纳入流程考量）

规划区 —— 紫色虚线框 / 标签对应「规划中」条目；带「已裁决」状态者为用户已拍板、待设计落地（如 M-3）

  • 06-review / review 命令（P1-a）ACCEPTED · 未落地
    在 validate→render 间插 Studio 审核 + must_review 硬闸；render-props 映射前移为 review/render 共用。验收：未确认 must_review ⇒ render 退出码 1 并列缺失条目 ref。
  • 创作期动效生成（P1-b）ACCEPTED · 未落地
    prompt 取自 motionboard.genPrompt（board 产出，提案 §4.5 2026-10-23 增补）→ MotionSpec JSON（零 codegen，复用 spec-loader/SpecRenderer），六道验收（注册 / paramsSchema / 画廊三帧 / 动效断言 / 确定性 lint / 版本化）后定稿入库；不在渲染管线内调 LLM，渲染期确定性红线不改。
  • M-1d 静音-词门控判据OPEN · 阻断线待校准
    告警档已落地（2026-10-24）：silentWordRatio 超过 SILENCE.wordRatioWarnMax=0.02 即告警、不阻断；告警线与静音探测参数绑定（单样本定线）。词时本身已由 M-1f 修复（按 SRT 窗口重铺并回写产物，kukini 静义词 9→0）；余阻断线需 2–3 条完整对齐素材。
  • 占位值校准（11 项 / 19 数值）待做 · 第一优先
    尤其 REWEIGH_COVERAGE_MIN=0.8（来源不明却已生效并写进产物）与 DENSITY.maxItemsPerCue（占位值却直接产 error，项目无 storyboard 编辑 UI，误伤成本高）。
  • 模板 11/11✅ 2026-10-24
    annotation/pointer-callout（四角括线 + 锚点 + target 标签）、transition/whip-pan（方向性速度线，触发 D3-a 确认闸）已实现并真渲抽帧确认。
  • pacing 语义化（M-3，用户已裁决 2026-10-23）已裁决 · 待设计落地
    LLM 读文案语义判分布，与 motionboard 同批产出；规则节奏表降级为无模型兜底先验；渲染期确定性红线不变（创作期自由、定稿冻结，同 2026-10-22 提案原则）。落地待办见断点表第 6 条。
  • hash 版阶段时序守卫待做
    当前 mTime 版（assertStageOrderIsSane）可被 cp / git checkout 改写绕过；计划烘焙时把上游 hash 写进 storyboard.meta 再比对。
  • 渲染基准量化取中位数（F4）待做
    已有 3 条成片样本（kukini 218MB / fast-0322 259MB / fast-0528 256MB），样本已够取中位数。
  • 探索项待评估
    shot 级 VLM 兜底（替代 F6 人审）；Qwen3-ForcedAligner 专用对齐（单次 ≤5min，长视频需切片，与可复现性立法意图有张力）。

五、关键断点与已知问题（影响流程理解的浓缩版）

完整 20 条评估见 docs/reviews/2026-10-23-pipeline-flowchart文档审查报告.md（A/B/C/D 四区，本次全部复核为真）。以下只列与「流程是否闭环」直接相关的条目。严重度：高 / 中 / 低。

#严重度断点（为什么计划改动非做不可）
1高must_review 计算但不硬闸：闸2 / 产路地产出 decision.review='must_review'，validate 仅生成警告队列，render 启动闸只强制 fullscreen —— 第二道闸的产物是「建议」而非「阻断」（定义了≠生效第六例）。P1-a 的硬闸即补此断点。
2高06-review 缺 review 命令：cli.ts 只有 init/align/perceive/storyboard/validate/render，审核无工具化入口，与断点 1 同源。

4中M-1d 静音-词门控仅告警档：silentWordRatio 超过 2% 告警但不阻断（阻断线需 2–3 条素材）。词时漂移已由 M-1f 修复（SRT 窗口重铺 + 产物回写，实测 9→0），本项余下的是防回归闸。
