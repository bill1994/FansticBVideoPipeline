# align —— 强制对齐与置信度门控

> **管线位置**：第 1 步 / 共 5 步
> **上游**：`jobs/<jobId>/00-input/` —— 已粗剪拼接、不含任何文字与特效的视频 + 对应 SRT
> **下游**：`jobs/<jobId>/01-align/` → 只有门控通过才允许进入 `perceive`

这一步是整条 pipeline 的**入口闸门**。对齐过不去，后面一步都不许开始 —— 这不是建议，是硬规则。

## 何时触发

- 拿到 `00-input/` 下的「已粗剪拼接视频 + SRT」时。
- `01-align/` 已存在时**默认不重跑**：阶段目录是不可变快照，下游产物基于它。只有上游素材变了才重跑，且重跑后 `02`–`06` 全部作废。

## 核心职责（三件，按序）

1. **抽音轨** —— 从视频抽 16kHz 单声道 wav。
2. **强制对齐** —— 以 SRT 文本 + 抽出的音频重新推导**词级**时间戳。
3. **置信度门控** —— 按阈值决定放行或阻断。

## 铁律

### 1. 只取 SRT 的文本，不信任 SRT 的时间戳

SRT 的时间戳是相对成片字幕轨的，而输入视频是**已粗剪拼接**过的，两者时间轴可能已经偏移。
因此：**文本来源 = SRT；时间来源 = 音频重新推导**。不得直接抄用 SRT 的时间戳。
（这条同时洗掉了「SRT 与拼接视频时间轴偏移」这个入口级风险。）

### 2. 强制对齐是 pipeline 启动前置步骤，不是可选增强

模型默认写词级锚点（`anchorMode: word`）。**没有词级时间戳，storyboard 根本没法起草。**
因此这一步不可跳过、不可延后。

### 3. 音频处理范围只做「对齐必需」

| 范围内 | 范围外（明确不做） |
|--------|------------------|
| 抽 16kHz 单声道 wav | 降噪、响度归一、BGM 分离、音频可视化 |

理由：降级已有「阻断 + 人工放行」兜底 —— 音质差 → 置信度低 → 阻断 → 人工处理，这条路已经通了。
不要在音频预处理上加投入。

## 必须停条件 —— 本 skill 存在的理由

> **不达标必须停。降级必须阻断，不允许静默降级。**

**门控阈值（初值，待实测校准）**

```
均值置信度 < 0.60   或   低置信词占比 > 30%   →   阻断
```

**阻断后怎么做**

1. **停下来**，不往下走，不自动降级到 cue 级。
2. 产出对齐报告，标注哪些词的置信度低于阈值。
3. 等人工显式确认。人工确认后，把放行信息写入 `06-review/confirmed.json`：

```jsonc
{
  "jobId": "...",
  "stage": "alignment",
  "reason": "对齐置信度低于阈值，人工核验后放行",
  "confirmedBy": "人工署名",
  "confirmedAt": "ISO 时间",
  "overrides": []
}
```

**结构上必须支持「跑完就停」**：人工确认发生在「跑完对齐之后、起草 storyboard 之前」。
实现上要能在这个点中断等输入，**不能一口气跑完再报错**。

> 阈值 0.60 / 30% 是初值，实测后校准。在校准之前，不要把这两个数当成有依据的结论去调。

## cue 级模式 = 人工签署的例外通道，不是降级兜底

低置信素材**不自动**走 cue 级。每次走 cue 级都是一次「有意识地接受精度损失」，必须留痕：

- storyboard 顶层 `meta.anchorMode` 必须写 `cue`（不能沿用默认 `word`）
- `meta.confirmedBy` / `meta.confirmedAt` 必须写清是谁、何时签的字

否则事后无法区分某一片到底是哪个精度出的。

## 产物（落 `01-align/`）

| 文件 | 来源 | 内容 |
|------|------|------|
| `audio.wav` | 【文档指定】 | 16kHz 单声道 |
| `words.json` | 【文档指定】 | 词级时间戳（每词含起止帧/秒 + 置信度） |
| `align-report.json` | 【实现期拟定，文档未点名】 | 整体均值置信度、低置信词清单、门控判定结果 |

> 文档只规定 `01-align/` 必须含「16kHz 单声道 wav + 词级时间戳 JSON」两者；具体文件名与第三个报告文件是本 Skill 的实现建议，可随实现调整，**但不得减少文档指定的数据内容**。

**放行后须回填给 storyboard 的字段**：`meta.alignmentConfidence`（整体均值）、`meta.fps`（顶层固化，后续改 fps 必须重新烘焙）。

## 失败与退出码

进程级语义化退出码（与其他阶段共用同一套）：

```
0 可交付 / 1 校验没过 / 2 参数错 / 3 版式✗ / 4 渲染失败 / 5 排队超时 / 6 内部错误 / 130 中断
```

| 情形 | 处置 |
|------|------|
| 门控未过 | **阻断**，退出码 `1`，等人工确认 |
| 输入缺失 / 参数错（无视频、无 SRT、fps 未知） | 退出码 `2`，不猜默认值 |
| 音频抽取失败 | 退出码 `4`，如实报错 |
| 超时或中断 | 退出码 `5` / `130` |
