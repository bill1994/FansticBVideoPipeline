# align —— 强制对齐与置信度门控

> **管线位置**：第 1 步 / 共 5 步
> **上游**：`jobs/<jobId>/00-input/` —— 已粗剪拼接、不含任何文字与特效的视频 + 对应 SRT
> **下游**：`jobs/<jobId>/01-align/` → 只有门控通过才允许进入 `perceive`

这一步是整条 pipeline 的**入口闸门**。对齐过不去，后面一步都不许开始 —— 这不是建议，是硬规则。

## 何时触发

- 拿到 `00-input/` 下的「已粗剪拼接视频 + SRT」时。
- `01-align/` 已存在时**默认不重跑**：阶段目录是不可变快照，下游产物基于它。只有上游素材变了才重跑，且重跑后 `02`–`06` 全部作废。

## 核心职责（三件，按序）

1. **抽音轨** —— 从视频抽 16kHz 单声道 wav。
2. **强制对齐** —— 以 SRT 文本 + 抽出的音频重新推导**词级**时间戳。
3. **置信度门控** —— 按阈值决定放行或阻断。

## 铁律

### 1. 文本与句子时间都以 SRT 为准，词级时间由音频推导

> 🔴 **2026-10-19 更正**：此处原写「只取 SRT 的文本，**不信任** SRT 的时间戳」。
> 该表述**不在 B2-fix 审核原文中**，是登记册转写时添加的过度推断，已撤回
> （见 `docs/decisions/OPEN-DECISIONS.md` 的 B2-fix 更正条目）。
> 保留原文会误导执行者去丢一个好数据源。

现状（`C2-6` + `M-1f`）三个数据源各有归属：

| 层 | 来源 | 说明 |
|---|---|---|
| 句子时间（cue 何时出现） | **SRT**（`srtFromSec` / `srtToSec`） | 用户对**这一份**素材手编的，实测与音频静音吻合 |
| 句子文字 | **SRT**（`cue.text`） | 逐字比对 0 差异 |
| 词级时间 | **音频**（whisper）→ 再按 SRT 窗口重铺 | 铺词逻辑唯一真源 `core/word-timeline.ts` |

**为什么仍必须做强制对齐**：`word:N` 锚点与「抢拍 -8f」这类手感，只有音频能给。
SRT 与音频是否对得上，由 `silencedetect` 交叉校验 —— **判据取自音频，不用 SRT 自证**。

### 2. 强制对齐是 pipeline 启动前置步骤，不是可选增强

模型默认写词级锚点（`anchorMode: word`）。**没有词级时间戳，storyboard 根本没法起草。**
因此这一步不可跳过、不可延后。

### 3. 音频处理范围只做「对齐必需」

| 范围内 | 范围外（明确不做） |
|--------|------------------|
| 抽 16kHz 单声道 wav | 降噪、响度归一、BGM 分离、音频可视化 |

理由：降级已有「阻断 + 人工放行」兜底 —— 音质差 → 置信度低 → 阻断 → 人工处理，这条路已经通了。
不要在音频预处理上加投入。

## 必须停条件 —— 本 skill 存在的理由

> **不达标必须停。降级必须阻断，不允许静默降级。**

**门控阈值（初值，待实测校准）**

```
均值置信度 < 0.60   或   低置信词占比 > 30%   →   阻断
```

**阻断后怎么做**

1. **停下来**，不往下走，不自动降级到 cue 级。
2. 产出对齐报告，标注哪些词的置信度低于阈值。
3. 等人工显式确认。人工确认后，把放行信息写入 `06-review/confirmed.json`：

```jsonc
{
  "records": [
    {
      "jobId": "...",
      "stage": "alignment",
      "reason": "对齐置信度低于阈值，人工核验后放行",
      "confirmedBy": "人工署名",
      "confirmedAt": "ISO 时间",
      "overrides": []
    }
  ]
}
```

> 🔴 **一个 job 可能要在多个阶段分别放行**（`F3-1` 裁决，2026-10-19）：
> `alignment`（本阶段）与 `render`（fullscreen 确认）是**两条独立记录**，
> 写在同一个 `records` 数组里，各自只对对应阶段生效。
> 顶层写单条对象的旧格式仍兼容；**同一 `stage` 出现两条会被判为配置错误**。

**结构上必须支持「跑完就停」**：人工确认发生在「跑完对齐之后、起草 storyboard 之前」。
实现上要能在这个点中断等输入，**不能一口气跑完再报错**。

> 阈值 0.60 / 30% 是初值，实测后校准。在校准之前，不要把这两个数当成有依据的结论去调。

## cue 级模式 = 人工签署的例外通道，不是降级兜底

低置信素材**不自动**走 cue 级。每次走 cue 级都是一次「有意识地接受精度损失」，必须留痕：

- storyboard 顶层 `meta.anchorMode` 必须写 `cue`（不能沿用默认 `word`）
- `meta.confirmedBy` / `meta.confirmedAt` 必须写清是谁、何时签的字

否则事后无法区分某一片到底是哪个精度出的。

## 产物（落 `01-align/`）

| 文件 | 来源 | 内容 |
|------|------|------|
| `audio.wav` | 【文档指定】 | 16kHz 单声道 |
| `words.json` | 【文档指定】 | 词级时间戳（每词含起止帧/秒 + 置信度） |
| `align-report.json` | 【实现期拟定，文档未点名】 | 整体均值置信度、低置信词清单、门控判定结果 |
| `whisper-ojf.json` | 【实现期中间产物，未入库】 | whisper 原始 `-ojf` 输出，供对账/排查；**不属于契约产物**，可随时删除 |

> ⚠️ 中间产物不是产物：`audio.wav` 与 `whisper-ojf.json` 在**对齐失败时也会留下**，
> 此时 `words.json` / `align-report.json` 不存在 —— 「阶段目录存在」≠「阶段成功」。
> 快照跳过判据要求 `words.json` 与 `align-report.json` **同时存在**，故此状态不会被误跳过。

> 文档只规定 `01-align/` 必须含「16kHz 单声道 wav + 词级时间戳 JSON」两者；具体文件名与第三个报告文件是本 Skill 的实现建议，可随实现调整，**但不得减少文档指定的数据内容**。

**放行后须回填给 storyboard 的字段**：`meta.alignmentConfidence`（整体均值）、`meta.fps`（顶层固化，后续改 fps 必须重新烘焙）。

## 失败与退出码

进程级语义化退出码（与其他阶段共用同一套）：

```
0 可交付 / 1 校验没过 / 2 参数错 / 3 版式✗ / 4 渲染失败 / 5 排队超时 / 6 内部错误 / 130 中断
```

| 情形 | 处置 |
|------|------|
| 门控未过（置信度 / `alignedRatio` 不达标） | **阻断**，退出码 `1`，写 `06-review/confirmed.json`（`stage:"alignment"`）后可由人工放行 |
| 输入缺失 / 参数错（无视频、无 SRT、fps 未知） | 退出码 `2`，不猜默认值 |
| **对齐结果为空**（whisper 一个词都没出，典型是 SRT 与音频对不上、或素材里根本不是人声） | 退出码 `2`。`--force` 重跑无效，先核对 SRT 与视频是否配套 |
| 音频抽取失败（ffmpeg 不可用 / 视频无音轨） | 退出码 `2`（`ConfigError`）。属环境或输入问题，**不是渲染失败** |
| 中断 | 退出码 `130`（由 shell 决定，本阶段不自行捕获） |

> ⚠️ 2026-10-19 端到端审计实测：`4` 在本阶段**从来不会出现**。
> 此前表里写「音频抽取失败 → 4」与实现不符（实现抛 `ConfigError` → 2）。
