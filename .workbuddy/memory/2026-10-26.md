# 第一档问题修复（同日第四轮）

## ① 主体检测 fail-open → 补进 W-F6-01

**根因**：`region-derive.ts` 策略是「框不到就退让（**不产 region**）」；
而 `checkSubjectUnknown` 只认 `shot.lowConfidence` / `region.lowConfidence` 两个标记 ——
连 region 都没有，哪来的标记？⇒ `collectHits` 遍历 regions 得零命中 ⇒ **遮挡校验静默空跑**，
报告照样 `0 error`。`geometry.ts` 的 `if (!safeArea) continue` 注释却写着「归 W-F6-01 的地盘」——
**空头支票**（与 `occludesSubject` / `handoffIn` / `DUR.exit` / 快照守卫同族，第 6 次）。

**修法（零新码，扩既有 F6 的覆盖）**：`occlusion.ts#checkSubjectUnknown` 第三段判
「shot 无任何 region **且该 shot 内确实叠了 overlay**」。两处收窄防噪音：
已在 lowConfidence 段报过的不重复报；空镜（无 overlay）不报。

**实测**：kukini 15 shot **0 条新增**（该素材 15/15 均有 region）——
说明该素材上问题未发生，但机制空白已补。

## ② 渲染期兜底三类 → 接线

**根因**：`stdio:'inherit'` 让父进程拿不到子进程输出 ⇒ 失败只能抛一句「渲染失败」，
`E-RT-01/02/03` 定义了一个月**从未被构造过**，`05-render/` 什么都不留。

**修法**：`execFileSync` → `spawn` + 流式转发（保住 20 分钟渲染的实时进度）
+ 累积尾部 200KB **原始 Buffer** → `classifyRenderFailure()` 子串分类 → 失败时写
`render-report.json`（`ok:false` + `failure{classified}` + `items` + `outputTail`）。
`runRender` 改 async（cli 与 review.test 加 await）；成功路径恒写 `items: []` 保持对称。
**判据写窄**：裸 `angle`/`gpu` 不参与匹配（`--gl=angle` 启动日志全是这词）；
三条都不命中 → `classified: null`，**不猜码**。

## 关键设计偏离（必读）

方案原文要求「把 `spawnSync` 改为可中断的 `spawn`」。**核对后没这么做**：
`cancel` 是**另一个进程**发起的，只需 `runnerPid` + `taskkill /T /F` 杀整棵树
（ffmpeg/whisper/chrome 全是树的子孙）。改 async 要把 `align` 整条链同步→异步
（波及 cli/测试/stdio 语义），收益为零。
⇒ 记录下：**父进程 pid 在阶段开始时就已知（`process.pid`）**，这是让方案简化的关键事实。

## 实现

- `core/pipeline-state.ts`：状态落 `jobs/<id>/pipeline-state.json`（**job 根**，不进阶段快照，
  避开 `assertNotWritingUpstream`）；**原子写**（`.tmp`+rename，防中途被杀留截断 JSON）；
  崩溃恢复判据是 **runnerPid 存活**而非时间阈值。
- `config.ts` 新增 **`EXEC_ORDER`（短名）**：`STAGE_ORDER` 是目录编号序（render 05 在 review 06 前），
  实际执行 review 必须先于 render（看片闸）—— 两个顺序混用会让 resume「先渲后审」。
- `cli.ts` 把 switch 抽成 `dispatchStage` + `runTracked` 统一包状态；新增 `cli-state.ts` 放三个命令。
- `resume` **停在 render 之前**（人工看片闸不可自动化绕过）。
- `status` 对 P1-2 之前的老 job 标 `◌ done?（有产物无记录）`；`render` 认 `render-report.json`
  而非 `render-props.json`（后者 dry-run 就有，会把「只 dry-run 过」误报成完成）。

## 踩到的四个坑

1. **USAGE 里嵌套反引号**把模板字符串提前闭合 → esbuild 报 `Expected ";"`。
2. **`EXEC_ORDER` 用了目录名**（`05-render`）而 CLI stage 是短名（`render`）→ 类型比较永远 false。
3. **`require` 在 ESM 里不存在**（typecheck 抓不到，运行时报 `require is not defined`）——
   `child-output.ts` 里我一度用 require 延迟导入。
4. **cancel 先调 reconcile 会把死 pid 修成 failed**，于是 cancel 抬头看不到 running，
   只回一句「无需取消」——用户刚看到 running 会以为坏了。改成 cancel 自己判断 pid。
