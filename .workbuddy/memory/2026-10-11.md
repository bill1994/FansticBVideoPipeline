# 2026-10-11

## 项目启动：Remotion 视频动效工作流（video pipeline）

用户目标：构建一套「接近全自动」的 Remotion motion-graphic overlay 工作流。
输入 = 已粗剪无字幕特效的成片 + 对应 SRT；输出 = 一个可渲染出片的完整 Remotion 项目。

用户给出的 5 阶段诉求：
1. Storyboard 生成（模型结合画面+文案 brainstorm 多个 motion idea）
2. 人工审阅与修改（改创意内容 / 调参数）
3. 产出到 Remotion Studio 预览
4. Studio 内继续迭代，改动回流项目
5. 最终交付可运行的 Remotion 项目 + 渲染导出

### 已决决策（grill-me session）
- **A1 自动化边界**（已决）：定位为「接近全自动 + 人在 storyboard 环节审阅」的半自动管线。
  AI 负责产 storyboard + Remotion 代码草稿；人审阅/修改 idea，再进 Studio 迭代，最终定稿渲染。
  产物 = 完整可运行 Remotion 项目。
- **B1 brainstorm 形态**（已决）：**混合式** —— 一份覆盖全片的完整 storyboard 为主体；
  对模型低置信/高风险的槽位额外挂 1–2 个备选 idea，人选一个。
  idea 带「置信度」元信息：高置信直接落地，低置信给备选让人拍板。
- **B2 storyboard 载体形态**（已决）：**C 方案** —— `storyboard.json` 为唯一真源；
  自动生成一份**交互式 HTML 编辑页**（缩略图 + 时间轴 + idea 表单：改文案/调参数/点选备选），
  点"导出"写回 json。这份 HTML 同时兼作 phase 3 的预览入口。
- **B3 感知管线**（已决）：两段式轻感知 —— ①场景切分 + 每 1.5s 抽关键帧（基准 1.5s，
  skill 执行时可提问让用户改更密/更疏）；②多模态模型给每帧**结构化打标**
  （景别 / 主体 region 粗定位 / 可留白区 / 氛围），非散文；③ffmpeg `silencedetect`
  抓语音停顿作为 motion 入/出点锚点（+ SRT 行切点）；④汇成 `timeline.json` 中间表示。
  定位精度 = **段级粗定位**（像素级 bbox 留到渲染阶段 D 再算）。
- **B4 动效生产机制**（已决）：**方案 C 混合** —— 建可扩展「motion 模板库」（每类 =
  参数化 Remotion 组件 + JSON schema 片段），brainstorm 主流走"选类型 + 填参数 + 写文案"；
  留 `custom` 逃生口，允许模型对特殊 idea 直产一次性代码（标高风险、必审）。
  注：原"95% 走库"是**方针修辞**，不是阈值参数。

### 阈值策略（框架已定）
- **两道闸串联，不并列**：
  - **闸1 路由**：`sim_max ≥ T` → template 产路 / custom 产路，决定"走哪条产路"。
  - **闸2 审核强度**：按 `confidence` 只调制"人工介入强度"（auto 落地 / 挂备选 / 必审），
    不改变产路。串联可避免同一模糊点被双重惩罚。
- **动态阈值**：`T = clamp( 间隙锚 , 约束于 配额锚分位 )`；配额锚 = 期望走库比例区间
  （建议 70%–90%）；间隙锚 = 分数排序最大间隙；
  **硬边界 `T_min=0.50 / T_max=0.80`**（用户原提的 50/80 降级为边界，不当取值）。
- **安全阀**：整批 `sim_max` 中位数 < 0.4 → 判"库不适配"，整批转 custom + 人审，**禁止降阈值硬套库**。
- **样本少**（单条/数据不足）→ 退化固定 `T=0.65`。
- schema 决策字段：每条 idea 存 `sim_max` / `confidence` / `routing: template|custom` /
  `review: auto|alternatives|must_review`。

## 外部调研（2026-10-12，WebSearch）

### 关键结论
- 主流 MG 分类（creamyanimation 16 类 / moonb 10 类）是"**做一条 MG 视频**"的分类，
  **大部分不适用于本项目**——本项目是"在**已有实拍**上叠 overlay"，不是从零做动画视频。
- 真正对标的先例 = **Remotion 自己的模板生态**。RVE 的 81 个免费 Remotion 模板分为 7 类：
  `Charts & Data(9) / Text(9) / Content Animation(9) / Background(9) / Cinematic(9) /
  Transition(9) / Logo & Branding(9)`。→ 可直接映射为模板库种子。
- 可参考的 Remotion 组件库/资源：Onda（70 组件 + 18 转场）、RemotionUI、Remotion Bits、
  snapcn、SwiftClip(30)、RenderComp Free(50, MIT)、remotion.dev/docs/resources。

### 已有 prior art（同类 agent skill，务必参考而非重造）
- `video-shotcraft`：agent skill，106 shot recipes + 161 motion previews。
- `Aeon`：agent 产 storyboard → 用 bundle 的 Remotion 项目渲染 MP4。
- `BrewReel`：LLM 只写 storyboard JSON → bundled Remotion 组件负责布局/动效/音乐/渲染。
- `remotion-qa`：渲染后检测"静音可读性"（dead air / 字幕被 UI 遮挡 / 移动端字号下限）。
- `audio-bed-check`：检查音频 bed 循环点与电平跳变（BS.1770 LU）。
- 来源：https://www.remotion.dev/docs/resources

### 分类修订（提案，待用户确认）
- 原 7+1 分类**不够**，漏了 4 类：`caption`（字幕/词级卡拉OK，生态最核心）、
  `cinematic`（影像处理：camera shake / ken burns / letterbox —— 有实拍，强相关）、
  `brand`（ident/水印/尾卡）、`sfx`（音效联动）。
- 原分类把"长什么样"和"放哪里（作用域）"混在一起 → 改为**双正交轴**：
  - **轴 A 功能族**（可扩命名空间）：caption / typography / data / annotation / carrier /
    brand / ambience / cinematic / transition / rhythm / sfx / custom
  - **轴 B 作用域 scope**（枚举）：`under-subject` / `overlay-safe` / `anchored` /
    `subject-transform` / `footage-transform` / `fullscreen`
- **可扩结构**：命名空间 `family/subtype@version`；registry.json 每模板强制契约
  `scope · layer · occludesSubject · paramsSchema · status(core|experimental|custom)`；
  版本锁定 pin → 不破坏旧 storyboard。

### 8 个可直接抄的机制
1. **模型只填表不写代码**（BrewReel）：模型只挑镜头 + 填文字，禁写坐标/帧数/颜色/CSS；
   `custom` 仅强模型本地模式开放，插件直接拒绝。
2. **三档校验器** `validate.mjs`：errors 必改 / warnings 尽量改 / human 列给用户；
   有 ✗ 不出片 → 补上"失败门禁"盲区。
3. **语义化退出码**：0 可交付 / 1 校验没过 / 2 参数错 / 3 版式自查✗ / 4 渲染失败 /
   5 排队超时 / 6 内部错误 / 130 中断。
4. **`revise.mjs` 一句话修改**（改一处不重写整份；受限 set/insert/remove on allowed paths；
   最多 3 轮；写入前备份；改完先校验）+ **`meta.tweak` 微调旋钮**（只 pace/textScale/
   headingFont/bg）→ 直接回答 phase 2/4 的"修改与回流"。
5. **custom 镜头围墙**：文字/数字只能经 slots 传入；静态检查拒绝硬编码文字数字与被禁
   import（给 file:line）；渲染前 tsc；安全区溢出/空白帧/冷冻动效归因到具体镜头；
   在渲染锁下跑 → custom 逃生口的完整实现蓝图。
6. **分段渲染 `lock.json`**：改哪页渲哪页，没改的复用 → 解决渲染成本盲区。
7. **确定性红线**（video-shotcraft #9）：禁 `Date.now()`/`Math.random()`；伪随机固定种子
   mulberry32/哈希，seed 从 index 派生，逐帧可复现。helpers: mulberry32/velocityAt/
   lagged/dampedSettle/handheld（vitest 单测）。
8. **渲染后测量，不信 composition 数字**（remotion-qa 核心洞察）：时长若由文字算出再断言
   时长够不够读 = 拿数字比数字，永远通过。必须测**渲染后的帧**。

### 根本差异（勿照搬）
这些 skill 都是"从零做一条视频"（纯图形/截图/AI 画面）；本项目是"在实拍上叠 overlay"。
→ 它们的 layout/主题 token 体系不可照搬；但通用部分（schema/校验/revise/确定性/
渲染后测量/卡点/workbench/分段渲染）可照抄。**"不遮挡主体"这块它们没有，必须自建**
（可借 remotion-qa 的 safezone 算法骨架）。

### 时间轴模型（进行中）
- **C1 轨道模型（含修订，已决）**：初版"轨道一等对象 + 同轨同时最多一个 item"被用户否决——
  用户明确要**同一层内 motion 可重叠**（如两段文字同时进）。定稿：
  - **`layer`（z 序，整数）与 `track`（作者分组/时间线）拆开**；同一 layer 可容多条 track。
  - **轨内 items 允许重叠**（表达同层并行元素）。
  - z 由 `layer` 决定；同 layer 内按声明序（后者在上），必要时给可选 `zIndex`。
  - **互斥改为按需显式声明** `exclusive: "<组名>"`（如 lower-third），默认不互斥；
    代价：互斥不再由结构保证，需在校验期/运行时查同 exclusive 组冲突。
  - track 保留价值：分组可读（HTML 编辑器一列）、挂 track 级属性（如"跟随主体 X"）、接力分组。
  - Remotion 映射：重叠 = `<Sequence>` 可重叠；z = DOM 嵌套/渲染顺序。天然对齐。
- **C2 时间坐标（已决）**：用户约束——**重剪罕见，"字幕对得准 + motion 帧精确"最重要**，不追求抗重剪。定稿：
  - **真相层 = 帧**：`storyboard.json` 最终落盘的是 `{fromFrame, durationInFrames}`，Remotion 直接吃。
  - **作者语法层 = cue 锚点 + 帧偏移**：模型用 `{anchor:"cue:12", offset:"-8f"}` 表达（**不让模型手算帧**，符合"模型只填表"哲学），
    生成时由 resolver **一次性烘焙**成帧并落盘。
  - **不设 `guard` 文本快照**（重剪罕见，砍掉防错位机制）。
  - 编辑页双显示：`帧 372 ｜ = cue:12 +0`（人既看帧也看归属字幕）。
  - `abs`（绝对帧/秒）作为手写逃生口。
  - 锚点粒度：**cue 级为主 + 词级可选**（词级来自 Whisper 逐词时间戳，仅需卡某词时用）。
- C3 跨段 span（基本被 C2 吃掉，只剩最小可见时长/边界对齐）/ C4 交叠互斥 / C5 穿插接力 / C6 Remotion 映射 —— 待钻。
