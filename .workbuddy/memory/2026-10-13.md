### 🔴 乐享 markdown 模式的三个新踩坑（重要，下次直接用）

1. **HTML 表格在 `render_mode=markdown` 下不可匹配。** `</table>` / `</td>` 这类标记**不在 block 文本里**，
   用它做 `old_str` 一律 `not found`。但**原生表格的单元格文本可以匹配**
   （如 `帧须落在目标词区间，否则 error` 一次命中）。
   ⇒ 想改表格**结构**（增行 / 删行），markdown 模式做不到，必须走 `render_mode=mdx` + `replace_blocks`。
   本次 §7.3 表因此改为「原表不动 + 表后加 §7.3 补录（GFM 表）」，已在 changelog 显式记录。
2. **改 A 处会让 B 处的匹配产生歧义。** 把 §1 的 `**一律人工确认**。` 改成带落点的版本后，
   它的文本**仍包含** `**一律人工确认**` 子串 → §6.6 的同类替换变成 `match_count=2` 无法精确命中。
   解法：先 `replace_all_matches=true` 统一替换，再删掉 §1 多出来的重复尾巴。
3. **代码块里的 `|` 匹配不上。** `alignment | storyboard | validate` 和 `alignment \| storyboard \| validate`
   都不命中。绕法：改用不含 `|` 的锚点 —— `validate",` → `validate | render",`。

另外：`update_content` 的 dry_run **遇到第一条 matched=false 就中止**，后面的不再报，
所以排查时要**一次只探一条**，或把最可能失败的放最后。

## 00:2x 用户质疑「align/perceive 需要重型模型？」 —— 我措辞失当，已核实并回应

用户问：能不能让多模态模型自己检测，不要额外配检测模型。

**先认错**：README 里写的「需要重型模型」是**措辞失当**。真正的问题是**契约不匹配**，不是"重"。

### 核实到的事实（可复用）

**align 侧 —— 不必出 Remotion 生态，也不必装 Python：**
- Remotion **官方**有 `@remotion/install-whisper-cpp`：装 whisper.cpp + GGML 模型，
  喂 16kHz mono wav，`tokenLevelTimestamps: true`（内部走 `--dtw`）→ **逐词时间戳 + probability**，
  正好就是 C2-2 门控要的每词置信度。
- 模型体积：tiny → base → small → medium → large-v3-turbo，**75MB ~ 1.5GB**。
- 性能：8.5 分钟视频，base.en + Metal 约 85 秒；CPU 也能跑（whisper.cpp 是 C++）。
- Windows 走预编译二进制，Unix 走 make —— 不依赖 Python。
- 备选：OpenAI Whisper API `timestamp_granularities: ["word"]`（但要联网、要 key）。

**⚠️ 但这里有个真实语义问题**：whisper 是 **ASR（自己听写）**，而 B2-fix 要的是**强制对齐**
（拿 SRT 文本当准绳、只推时间）。whisper 听出的词与 SRT 未必逐字一致。三条路：
- (a) 用 whisper 的文本当词表（锚点索引它，自洽），SRT 退为交叉校验 —— 最省事
- (b) whisper 出时间 + 把它的词序列**文本对齐**回 SRT —— 保住 SRT 权威，中等工作量
- (c) 上真正的 forced aligner（wav2vec2/CTC，要 Python/torch）—— 最贴原文，但要装 Python 栈
**我倾向 (a) 或 (b)。这条待用户裁决。**

**perceive 侧 —— VLM 做不了，有硬证据：**
- 架构层：VLM 视觉编码器把像素变成语义 patch token，**没有内部坐标系**；
  它输出 "30%" 是"预测下一个 token"，不是"测量"。
- 实测（有人做过 5 轮补救：直接提示 → 边缘标尺 → 密集网格 → 换多家 VLM → 多轮裁剪）：
  **全部失败，偏差 20–40%**，小模型甚至整图一个框。
- Qwen2.5-VL 的 grounding 准确率**随提示措辞在 15%–82% 之间摆** → 直接杀死可复现性。
- 前沿 VLM 在 grounding 任务上 IoU 只有 **0.09–0.13**。
- 我们要的是**遮挡比例**（人脸 0% / 手持物 ≤20% / B-roll ≤30%），差几个百分点就是过/不过。
- 量也不允许：1.5s 抽帧 × 30 分钟 = **1200 帧**。
- D2 还要**关键点**，VLM 不给；B-roll 的「显著性峰值区」是数值计算，不是语言任务。

**但 perceive 也不需要"重型"**：MediaPipe 模型是**几 MB 级** ——
`pose_landmarker` 5.8MB、`pose_landmarker_full` 9.4MB、`hand_landmarker` 7.8MB、
`face_detector` 230KB、`image_segmenter`(Selfie) 250KB、`object_detector` 7.3MB。
CPU 可跑（实测 720p 下手部约 28FPS）。B-roll 显著性可用经典谱残差法，**零模型**。

**学界/工业界的共识方案是 composite pipeline**：检测器管 where，VLM 管 what/why。

### 我给的结论（未落地，等用户定）
1. align：走 `@remotion/install-whisper-cpp`，**不出 Node 生态**。需要先裁决上面 (a)/(b)/(c)。
2. perceive：要检测器，但是几 MB 级的小模型，不是"重型"。运行时两选择 ——
   MediaPipe Python（`pip install mediapipe` 一行，但项目里多一个 Python 工具）
   vs 全 Node（onnxruntime-node / MediaPipe WASM + canvas 垫片，代价是适配层）。
   **这正是我把它做成 `PERCEIVER_CMD` 适配器的原因**：把选型决定留给用户，而非替他钉死。
3. VLM 的位置：**storyboard 起草**（挑模板/写文案）本就是它的活；
   另可加一层 **shot 级二次判定**（全片仅 20–60 次调用）替代 F6 的人工兜底。
4. 若想彻底省掉检测：**不建议** —— 校验项 #12/#14 会从「测量」退化成「声明」，
   「不遮挡主体」这条硬约束就失去唯一证据来源；且 D1/D2 是已封口裁决，要改须回登记册开一条。
