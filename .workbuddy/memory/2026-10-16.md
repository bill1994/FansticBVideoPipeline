🔴 **踩坑（已写进 MEMORY.md 雷区）**：推送一开始连续 5 次失败
`Failed to connect to github.com:443 over proxy 127.0.0.1 after ~2055 ms`。

- **根因**：我在命令里写死了 `-c http.proxy=http://127.0.0.1:4436` —— 那是**上午**的端口，
  下午宿主已换成 `11542`（同日 `CODEBUDDY_SERVICE_PROXY_URL` 也从 `8113` → `1965`）。
  写死的旧端口覆盖了正确的环境变量 ⇒ git 被指向死路。
- **误导点**：同时段 `curl https://github.com` 是 **200**，看起来"网是通的" ——
  因为 curl 走的是环境变量里的新端口。**两边用的不是同一个代理，不能用 curl 通推断 git 通。**
- **修法**：直接 `git push origin main`，不加 `-c http.proxy`，让环境变量生效 → 一次成功。
- ⚠️ 另一个自摆乌龙：首次判定脚本写成
  `if git push … | tail -8; then … grep -q "$(ls-remote …)"` ——
  ① 管道让 `if` 判的是 `tail` 的退出码（恒为 0）；② `ls-remote` 同样失败时命令替换为空，
  `grep -q ""` **匹配一切**，于是打出假的 `PUSH-OK`。
  **教训：验证推送必须比对完整 hash 字符串相等，别用"包含"判定，也不要把命令接在管道后面判退出码。**
