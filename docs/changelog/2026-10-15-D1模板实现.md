## 1. 病根不是"没写模板"，是"没有映射表"

### 1.1 原状

`src/templates/builtin.ts` 里 10 个模板的声明齐全（`id`/`scope`/`layer`/`footprint`/
`paramsSchema`/`minVisibleInFrames`），但：

- `registry.ts` 的 `getTemplate()` 只返回**声明**（纯数据）；
- **从 `motion id` 到 React 组件之间没有任何映射**；
- 于是 `MotionItem.tsx` 只能统一画一个灰框 —— **10 个模板渲染结果逐像素相同**。

### 1.2 为什么这类退化能一路逃过所有防线

这是本日最值得记的一条，因为它揭示了**现有验证体系的盲区**：

| 防线 | 为什么抓不到 |
|------|-------------|
| 16 项构建期校验 | 纯 JSON→JSON 结构判定，**根本不读渲染结果** |
| `npm run typecheck` | 占位块是合法 TSX，类型正确 |
| 原有 183 项单测 | 无一条断言渲染产物 |
| `render` 阶段 | 成片能正常导出，**不报错** |
| Remotion 渲染本身 | 灰框也是合法的画面 |

⇒ **只有一条"直接断言渲染输出的测试"能兜住它。**
已按计划书 1.4 补上（见 §4）。

## 2. 顺带发现的真缺口：字幕模板在数据层面根本无法实现

### 2.1 矛盾的契约

`caption/karaoke-word` 的 `paramsSchema` **刻意不含 `text`**，
理由写在 `builtin.ts` 注释里（P1）：字幕文本来自 SRT，模型若也能写 text，
就会出现「字幕与语音对不上」，而时序校验只看帧区间、**任何校验项都拦不住**。

这条设计是对的。但——

🔴 **渲染期原本没有任何地方读 `01-align/words.json`。**
声明层刻意不给 `text`，实现层却没有替代来源，
`MotionItem.tsx:35` 只能去读 `item.params.text`（一个校验项 #16 会拦掉的键）。

**⇒ 字幕模板此前不是"没写"，是"写不了"。**
若只补组件而不接数据通道，`karaoke-word` 会渲染出一段空字幕带，
而校验全绿、类型检查通过、单测全过 —— 又一次"看起来完成"。

### 2.2 补的通道

新增 `src/remotion/caption.ts` + `RenderProps.caption` 字段：

```
01-align/words.json → toCaptionData() → props.caption → CaptionData → karaoke-word
```

- **`toCaptionData()` 严格容错**：结构不符 / NaN / Infinity 一律降级为空通道，
  **不抛错**。理由：字幕数据缺失应让一个模板少显示几个字，
  而不该让整条渲染管线崩掉 —— 后者把「一个模板的数据问题」
  升级成「成片渲不出来」，代价完全不成比例。
- 🔴 **文件缺失时整个省略 `caption` 字段**，`render.ts` 出 `log.warn`。
  **绝不用 storyboard 里的文字凑** —— 那正是 P1 要防的第二个来源。

实测 demo：`60 词 / 6 cue` 已正确注入 `render-props.json`。

## 3. 令牌层：不让"禁颜色"只禁 params

P1 禁模型写颜色/坐标/帧数。`builtin.ts` 注释明写
「高亮色由渲染期按命名令牌（`brand`/`accent`）解析，不经 params」。

那么"按命名令牌解析"具体解析成什么色值？答案必须落在代码里且**只有一处**。
若无此层，各组件只能各自内联 `#RRGGBB` ⇒令牌层零消费（问题 9 的同款病）、
换肤要改 N 个文件、"禁颜色"实际只禁了 params —— **等于自欺**。

新增 `src/remotion/tokens.ts`：`COLOR` / `FONT` / `RADIUS` / `DUR` / `SHADOW`。
组件内**零字面色值**。

字体用系统栈、不引 Web Font：`E-RT-01`（字体未加载即 error）存在，
而引 Web Font 会新增「下载失败 / 字体缓存 / 各机不一致」三个失败模式，
首批模板不值得为此引入 `delayRender` 等待。

## 4. 组件契约：整个渲染树只读一次时钟

### 4.1 组件**不调** `useCurrentFrame()`

`TemplateProps` 把 `frame` 作为 prop 传入，`MotionItem` 是唯一读取点。三个理由：

1. **可测**：`renderToStaticMarkup(<X frame={12} …/>)` 直接可跑，不必包 Provider，
   且**能断言「不同帧产出不同 DOM」** —— 这是「动效真的在动」唯一可靠的自动化判据。
2. **唯一读取点**：满足 E2 确定性红线时，出错只需查一处。
3. **纯函数**：`frame → JSX`，服务端渲染与 Studio 预览必然一致
   （否则 Studio 看到的和渲出来的不一样，排查成本极高）。

### 4.2 测试覆盖（计划书 1.4）

新增 **35 项**（218 - 183）：

| 文件 | 项数 | 断言什么 |
|------|------|---------|
| `tests/template-render.test.tsx` | 16 | ① 5 模板同帧输出**两两不同** ② 同模板不同帧输出不同 ③ 映射表与声明表 id 逐字对应 ④ 未实现模板**带缺失标记** ⑤ 参数缺失/非法预设不崩 |
| `tests/caption.test.ts` | 19 | 通道容错、取词窗口、高亮判定、纯函数一致性 |

**第① 条就是防灰框的核心断言。** 报错信息直接指出是哪两个模板撞了。

## 5. 🔴 探针抓到的第二个缺陷：4 个模板**只入场不出场**

### 5.1 怎么发现的

新写了 `tools/render-probe.mts`：SSR 渲染各模板若干帧，统计**逐帧差异**。
第一版只比「入场帧 vs 中段帧」，输出：

```
kinetic-line   f0→f30:85    f30→f55:0    ← 中段完全静止
lower-third    f0→f30:593   f30→f55:0
tag-float      f0→f30:236   f30→f55:0
stat-card      f0→f30:521   f30→f55:0
```

中段静止本属预期（motion 停住让人读）。**但 f55 是末尾帧**——
它该是**出场**。逐一打点后确认：

```
入场 f0..f11 活跃 → 中段 f12..f49 **静止 38 帧** → 末尾直接消失
```

`DUR.exit = 0.18` 与 `enterExitFrames().exit` **定义了却只有字幕模板在用**
⇒ 4 个模板表现为「弹一下 → 定住 → 突然消失」，成片里是廉价感最直接的来源。

### 5.2 与问题 9 同款病

| | 问题 9 | 本次 |
|---|--------|------|
| 症状 | 字段/令牌定义了没人用 | 同|
| 位置 | `occludesSubject` / `handoffIn`（契约层） | `DUR.exit`（令牌层） |
| 为何逃过检查 | 16 项校验不读该字段 | 无任何检查看"出场是否发生" |
| 后果 | 文档说承重、代码没读 | 令牌声明了、模板没接 |

⇒ **教训一致且可推广：新增能力必须当场接入消费方，否则等于没做。**

### 5.3 修法

`tokens.ts` 新增共用的 `enterExitProgress(frame, duration)` + `fadeInOut()`，
5 个模板统一改用它（原先 4 个各写各的 `interpolate`，现已归一）。

**各模板的出场方向按物理直觉分别设计**（不是统一淡出，那才叫偷懒）：

| 模板 | 入场 | 出场 |
|------|------|------|
| `kinetic-line` | 左侧推入 / pop 缩放 | **轻微放大后淡出** |
| `lower-third` | 横向推入 | **向左推出**（来去同轴） |
| `tag-float` | 上浮 +24px | **下沉 -16px** + 微缩 |
| `stat-card` | scale 0.9→1 落定 | **缩到 0.96** |
| `karaoke-word` | 淡入 | 淡出 + 底板延迟 |

修复后实测：

```
kinetic-line  f12=0  f50=136  f59=95    ← 出场回来了
lower-third   f12=0  f50=626  f59=623
tag-float     f12=0  f50=315  f59=48
stat-card     f12=0  f50=572  f59=31
```

并把判据固化为单测「**每个模板的出场帧必须与中段静止帧不同**」——
只验「入场在动」会漏掉「出场没做」这个方向。

## 7. 两条设计决策（都有理由，不是随手）

### 7.1 未实现 ≠ 画成别的

查不到实现时落 `Placeholder`，且：

- 打 `data-template-missing="1"`；
- 视觉上**故意做丑**（黄色斜纹+ 虚线框 + `未实现：<id>`）。

理由：`validate` 阶段**不知道**渲染层实现情况（它不读渲染产物），
所以"欠一个实现"这条信息**只存在于成片里**。
必须让它显眼，而不是伪装成已完成 —— **诚实留空优于占位冒充**。

⚠️ 反过来说，这条信息**只有审片人看得到**，程序层面无告警。
已由`assertRenderMapValid()` 在启动期兜住 id 拼错这一类静默退化。

### 7.2 `stat-card` 刻意**不做** digit roll

D3b 把 `DigitRoll.tsx` 列为可借鉴的「实现参考」，第一轮仍不做，三个理由：

1. 第一轮目标是「证明管线」（§4.2 R1），滚动属第二轮打磨范围。
2. **滚动正确性依赖数值语义**，而 `value` 是**字符串**，
   且校验项 #16 明确「不判语义」（`"999%"` 结构正确）。
   ⇒ 渲染期**无从判断该不该滚、滚几位**。
   没有语义依据的动画就是猜，猜错的表现是「价格牌数字滚完变成 00899」。
3. 需先立「数字语义」裁决（是否含小数/千分位/货币前缀），不该在实现期顺手定。

## 12. 第二轮打磨：缓动 + 参数手感表（计划书 1.7）

### 12.1 🔴 发现：全程线性插值

第一轮的 `enterExitProgress` 用的是**线性**：
```
enterP = clamp01(frame / enter)
```
⇒ 30fps 下 60 帧 motion 的入场只有 10 帧，linear 在第 2 帧才走 10%，
观众看到的是「缓慢爬升」—— 这就是「廉价感」的第二大来源
（第一大是昨天修的「没有出场」）。

### 12.2 曲线选型：**实测数值**，不凭感觉

把候选曲线在 t=0.1/0.2/0.3 的推进量打出来：

| 曲线 | t=0.1 | t=0.2 | t=0.3 | 结论 |
|---|---|---|---|---|
| linear | 0.100 | 0.200 | 0.300 | ❌ 匀速，机械感 |
| cubic-out | 0.271 | 0.488 | 0.657 | 温和，不够利落 |
| **expo-out (0.16,1,0.3,1)** | **0.494** | **0.752** | **0.877** | ✅ **入场选用** |
| back-out (0.34,1.56,..) | 0.404 | 0.703 | 0.907 | ❌ t=0.5 达 **1.087 超调 8.7%** |

**出场选`cubic-in`** 而非 expo-in：expo-in 在 t=0.9 已达 0.506，
最后一段几乎消失，配上字幕像"字被吸走"，反而廉价。

### 12.3 🔴 为什么不用 back-out（回弹）
它超调 8.7% ⇒ 元素短暂越出 `footprint`。
而 `footprint` 语义是「**取全动画期最大包围盒**」（`types.ts`）
⇒ **超调属契约违反**，不是视觉细节。字幕尤其不能超（会溢框）。

已固化为单测：入场/出场进度**必须单调不减且上界为 1**。

### 12.4 配比调整

| 参数 | 第一轮 | 第二轮 | 理由 |
|---|---|---|---|
| `DUR.enter` | 0.18 | **0.16** | 入场要利落（观众在等信息） |

### 12.6 🔴 手感表实测纠正了我自己的错误

初稿我写「kinetic-line >6 字就溢出」，真渲测 16 字才发现：
**806px 的框能放约 14 个中文字**，我低估了近 3 倍。

真渲（16 中文字 + `123456789`）结果：**4 个模板全部溢出**，
`stat-card` 甚至**溢出画面边界**。

⚠️ 关键：`whiteSpace: nowrap` 意味着**溢出既不折行也不缩放**
⇒ 模型填长文本会让成片出现跑出画面的文字，
**而 16 项校验完全看不出来**（全是结构判定，不读渲染结果）。

**两条可选处置均未实施、待裁决**（详见手感表 §7）：
A 渲染期自适应（破坏「字号即层级」语义）；
B 构建期校验（需先改登记册，且引入**依赖字体度量估算**的判定，
估算不准就会误伤合法创作 —— 即 D5 风险 R6 的具体化）。

**当前默认假设**：模型起草遵循 SKILL.md 的字数建议。
**这是纪律，不是强制。**

### 12.7 一个测试教训

改 `DUR.enter` 后 `template-render`挂了 —— 但**不是代码错**：
配比 0.18→0.16 使入场从 11 帧缩到 10 帧，而测试取 `frame=10`
恰好落在入场刚结束处、位移归零。

⇒ **测试不该硬编码一个会随调参漂移的帧号**。
已改为取「入场期内的帧」（`frame=2`），并在手感表里立为调参纪律。
