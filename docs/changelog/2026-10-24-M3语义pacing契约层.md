# 2026-10-24 · M-3 语义 pacing 契约层落地

> M-3（2026-10-23 用户裁决）：pacing 首选路径 = LLM 创作期语义判定，
> 规则节奏表降级为兜底先验（不退役），渲染期确定性一字不改。
> 本日落地的是**契约层**——语义判读发生在会话 AI（创作期），不是往管线里接模型 API。

## 落了什么

1. **类型契约**（`core/types.ts`）：
   - `RhythmTable.meta.source?: 'rules' | 'semantic'`（缺省 = rules，向后兼容已落盘产物）；
   - `RhythmCue.signal` 放宽为 `(RhythmSignal | string)[]` —— 语义判据
     （「铺垫」「反讽」「口头禅」…）天然不在结构词表里，LLM 自述依据本就是裁决的一部分。
   - 规则路径的消费者（params 预填 / intent 提取）在调用点收窄（`isRuleSignal`），
     非词表值静默剔除 —— 语义判据本来就不是给机械提取用的（`core/rhythm-rules.ts`）。

2. **一致性校验**（`validate/context.ts#assertPacingConsistentIfPresent`，M-3 ⑤）：
   走 buildContext 结构断言层，ConfigError 退出码 2，**不占 18 项名额**。三条判据：
   - cue 索引存在性 —— pacing 引用的 cueIndex 必须真存在于 `words.json`；
   - motion id 已注册 —— 防自造模板 id（与校验 #16「模型不能自造键」同精神）；
   - decide 与条目对齐 —— `decide:'motion'` ⟺ motion 字段存在。
   无表不拦（no-subtitle 天然无表；一致性只对存在的表负责）。

   🔴 **刻意不校验「pacing 与 board 的分布一致」**：语义路径的价值恰恰是模型可以
   合法偏离规则先验（语义优先于规则），硬绑等于锁死这个能力。
   「pacing 决定 motionboard 分布」的对账手段是人工核对 reason 留痕。

3. **SKILL 契约同步**（根 SKILL.md + `.workbuddy/skills/storyboard/SKILL.md`）：
   模型按语义判读每条 cue，产出 decide/motion/signal（自由文本）/reason（自述依据），
   与 motionboard 同批落盘并写 `meta.source:'semantic'`；reason 是因果对账凭据不是装饰；
   规则底稿是先验参考，可合法偏离。

4. **复现性口径更正**（M-3 ④）：「同一份 SRT 必须产出同一份节奏表」**只对规则兜底
   路径成立**（`types.ts` / `rhythm.ts` 注释收窄）——语义路径由 LLM 创作期判读，
   随机性关在创作期，渲染期确定性不受影响。
