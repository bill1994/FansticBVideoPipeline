## 3. D-B2：逐模板文本度量实测表

**工具**：`tools/measure-text-metrics.mts` + `src/remotion/probe-entry.tsx` +
`src/remotion/gallery/TextMetricsProbe.tsx`（探针合成不进成片 / Studio）。

方法：真实模板组件（`MotionItem` 主链）在纯洋红背景、full-screen footprint 下，
对 CJK 与数字各渲 1 / 2 / 10 字，按文字颜色取包围盒，线性拟合 px/字 与 em。

**实测结论（6 个文字模板）**

| 模板 | CJK em | 数字 em |
|---|---|---|
| `typography/kinetic-line` | 1.000 | 0.617 |
| `typography/lower-third` | 1.000 | 0.620 |
| `typography/tag-float` | 1.000 | 0.615 |
| `typography/center-emphasis` | 1.000 | 0.616 |
| `data/stat-card` | 1.000 | **0.667** |
| `annotation/pointer-callout` | 1.000 | 0.617 |

**契约改动**：`TextMetrics` 拆成两把尺子 ——
`charWidthEm`（CJK，缺省 1.0）+ `latinWidthEm`（数字/拉丁，缺省 0.5）。
单一系数乘两个基准表达不了「CJK 1.0 + 粗体数字 0.667」，先前的「折中调参」方向是错的。

**顺带统一渲染期口径**：`fitScale` 原先 `padding×2`（校验器只减一次）、且不接收
逐模板系数（渲染期永远按 0.5em 估数字）。现改为 padding 减一次 + 传入
`charWidthEm`/`latinWidthEm`，渲染期与校验期只剩 15% 余量的保守差。

**🔴 同时更正两处旧结论**：
2026-10-15 记录的「`tag-float` 16 字撑破胶囊 / `stat-card` 9 位溢出画面」
在**声明 footprint** 下无法复现（427px < 576px、315px < 614px）。
旧观测应来自被覆盖的 footprint；现以 `docs/templates/2026-10-24-文本度量实测表.json/.md` 为准。
#17 仍为 warning 不阻断，升 error 需另立裁决。
