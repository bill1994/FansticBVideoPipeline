# cue 化字幕 + 影子载体轨 · 第二轮真渲

> 日期：2026-10-18（接 `2026-10-18-真素材端到端首跑.md`）
> 依据裁决：`C2-6`（`cue:N` 锚点）、`D4-t3`（影子载体轨 + 最内层）
> 目的：让字幕按 cue 切分（首轮成片里糊成 3–5 行文字墙），并让 tier2 载体退让真正改变画面

---

## 1. `cue:N` 锚点（C2-6）

**动机**：字幕按 cue 切分时，模型不该手算「显示多少帧」。首轮用「大窗口」起草，
一条 item 覆盖 8–31 秒 ⇒ 成片里出现 3–5 行文字墙（`caption/karaoke-word` 渲染的是
**窗口内全部词**，不是当前一句）。而改成「一条 cue 一个 item」后，模型必须自己算
每条 cue 的时长 —— 48 条 cue 手算 48 次，正是铁律 2 要禁的事。

**实现**（`core/bake.ts`）：

| 语法 | 起点 | 隐式时长 |
|---|---|---|
| `cue:N` | `cues[N].fromFrame + offset` | `cues[N].toFrame - fromFrame + 1` |

- 显式 `durationInFrames` **仍优先**（沿用时长来源优先级第 1 条）
- `BakeRecord` 新增 `cueIndex`，与 `wordIndex` **互斥**（`-1` 表示不适用），避免把 cue 序号误当词序号
- `stages/storyboard.ts` 把 `aligned.cues` 一并传给 `bake`

**结果**：草稿 48 个 caption item（`attack: cue:0..47`），storyboard 里能直接看出
「这条字幕覆盖哪一句」。

## 2. 影子载体轨（D4-t3）

**动机**：首轮记录 §5 的遗留 1 —— `validate` 把 tier2 的 `window` 写进**叠加 item** 的
`carrier.params`，而渲染层按 **track 的 motion scope** 划分载体轨，`MotionItem` 不读
`item.carrier` ⇒ **两条路径不相交，报告说退让了、画面分毫未动**。

**实现**（`remotion/carrier-synth.ts`，纯函数 + 单测）：

- 从「带 `carrier` 的**叠加** item」合成一条**影子载体轨**（`motion = carrier.template`、
  `params = carrier.params`、区间同该 item），并入 render props 的 `carrierTracks`
- **只在该 carrier 真的生效过时合成** —— 判据是 `params.window` 存在
  （`occlusion.ts` 终判通过后才写）。缺它说明 tier1 平移就解决了，
  此时再切画面是**无中生有**：观众会看到一段没来由的分屏。**声明 ≠ 生效**
- 影子轨只进 `05-render/render-props.json`，`03-storyboard/storyboard.json` 保持原貌

## 3. 🔴 第三个 bug：载体轨嵌套会叠加时间偏移（本轮真渲抓到）

**症状**：影子轨**单独存在**时完美分屏；一旦外层还有 `punch-in`（真实载体轨），
**加了等于没加** —— 像素/SSIM 实测 `All: 1.000000`（完全一致）。

**根因**：`CarrierChain` 用 `reduce` 把多条载体轨**嵌套**包裹 children，而
`<Sequence from={x}>` 是**相对父级**偏移时间的：

```
内层起始 = 父层偏移(2744) + 自身 fromFrame(6488) = 9232 > 成片长度 6667
```

嵌套 n 层就叠加 n 次偏移，而 `item.fromFrame` 是**绝对帧**。
补 `from={0}` 也没用 —— 偏移发生在每一个 `<Sequence>` 上，而变换必须包住视频就只能嵌套。

**修法**：**把时间轴拍平**，不再嵌套。

1. `composeCarrierTimeline(tracks, total)`（纯函数）：取所有载体 item 的起止帧作切点，
   把时间轴切成**原子窗口**，每窗最多挂一个变换；
2. `CarrierTimeline` 组件：外层 `<Sequence from={0}>`（零偏移），逐窗
   `<Sequence from={w.from}>` → 有变换则套 `MotionItem`，否则原样透传 children。

**副产品**：首轮那个「载体窗外视频消失」的 bug 在结构上不可能再复发 ——
窗口覆盖 `[0, total)` 无缝无叠（有单测断言逐段相接）。

⚠️ **已知边界（诚实记录）**：两个载体时间**真正重叠**时取「数组靠前者（更内层）优先」，
外层的变换在该窗口被丢弃。D4-t2 已记「同 track 内载体重叠语义未定义」，跨 track 同理；
此处取确定性降级，而不是让两条变换叠乘（那会产生没人能预期的画面）。
若真实素材需要「放大 + 分屏」同时生效，**应先立裁决再改**。

## 4. validate 结果与两条判据的适用范围

`validate` 通过：**error 0 / warning 104**。构成：

| 码 | 条数 | 说明 |
|---|---|---|
| `W-C3-01` | 49 | 起点恰好落在词级边界 —— **48 条来自 cue 锚定的字幕**（字幕本就该对齐语音），1 条来自 tag-float |
| `W-C4-01` | 7 | footprint 相交（首版 54 条，见下） |
| `W-D2-01` | 1 | tier1 平移消解 handheld 遮挡（25.1% → 9.3%） |

⇒ 两条判据对「cue 化字幕」**过于敏感**，属于「判据适用范围」问题（不是 bug）：

- `W-C3-01` 的立法意图是「机械对齐让人读起来像机器」，而**字幕对齐语音恰恰是目的**；
- `W-C4-01` 首版报了 **54 条**，全是**同一条字幕轨上相邻 item 的 1 帧重叠** ——
  根因是我把 cue 时长写成了 `toFrame - fromFrame + 1`（按 `Cue.toFrame 含端点` 的字面理解）。
  实测反证：对齐产物里 `cues[i].toFrame === cues[i+1].fromFrame`，说明它是**分界点**而非末帧，
  当**半开区间** `[from, toFrame)` 才是正确读法。改成半开区间后：
  `W-C4-01` 54 → **7**，成片里每条字幕不再多出邻句的字（首版实测「的是 … 前」）。
  这条**已改**（`bake.ts` 的 `cueDurationInFrames`），因为它同时是可见的画面缺陷，不只是告警噪声。

**第四条修正（同轮真渲）**：半开区间之后，成片里每条字幕**头部**仍多一个上一句的字
（实测「的是 Spiridon Cage 的中底配置」）。根因是 `wordsInWindow` 用 `w.endFrame >= fromFrame`
判交集 —— 上一句的末词 `endFrame` **恰好等于**本句 `fromFrame`（对齐产物里 cue 分界就是这么排的），
于是被算进本句。改成严格大于 `w.endFrame > fromFrame`：只排除「恰在边界上收尾」的词，
仍保留「跨越边界的词」（避免缺字）。真渲单帧复验：字幕变为「Spiridon Cage 的中底配置」。

两者都建议**收窄适用范围**（字幕家族 / 同轨相邻 item 豁免），但这属于改判据，
须先走登记册。本轮**只记录、不改**。

## 6. 第五处修正：字幕的**时间与文字都改以 SRT 为准**（用户反馈驱动，C2-6 补正）

**用户反馈**：「字幕拆开后看得不连贯，能不能按我给的 SRT 那样拆，那时我已经编辑好拆分的字幕」。

**先核事实**：`cues[]` 的文本与 SRT **逐字比对 0 差异**，48 条、切分位置一致 ——
所以「怎么拆」本来就已经是 SRT 的；问题在**时间**。

**证据**：抽 10.3 秒的帧，画面是一段静音 B-roll（鞋特写，`volumedetect` 实测 −58 dB），
字幕却在显示「它把 spirit Donkage 的中底和 cookie 的」—— 这句话 SRT 说 **15.13 秒**才说，
`cues[2].fromFrame` 却给出 **8.07 秒**，早了 **7.06 秒**。

**两层根因**：

| 层 | 病 | 现状 |
|---|---|---|
| 时间 | `outCues` 的帧区间取**词落点**（`builtin-align.ts` 注释原文「时间来自音频，不是 SRT」），而 whisper 把 7 秒静音并进一个分段 ⇒ DP 只能把词平摊在静音里 | 改：`Cue` 增 `srtFromSec`/`srtToSec`（类型里早已声明，此前**从未写入产物**），`cue:N` 锚点改取 SRT 时间 |
| 文字 | `karaoke-word` 用「窗口内落进的词」拼字幕 | 改：**取 `cue.text`**，词只经 `highlightSpan` 在原文里定位高亮 |

🔴 **为什么第二层必须一起改**：如果只把时间换成 SRT，词还漂在 8–14 秒，
窗口里就会落进**别的句子**的词 —— 字幕文字会错得比现在更离谱。
「时间用 SRT、文字用 SRT、词只负责高亮」三者必须同时同口径。

**降级语义**：词与原文对不上时 `highlightSpan` 返回 `null` ⇒ 整句不高亮，但**内容仍是对的**。
宁可某句不亮，也不能显示错句子。

**结果**：

| 指标 | 改前 | 改后 |
|---|---|---|
| 10.3 秒（静音空镜） | 有字幕（错句） | **无字幕** ✓ |
| 15.8 秒（实拍口播） | 无字幕 | 显示「它把 spirit Donkage 的中底和 cookie 的」✓ |
| `W-C3-01` | 49 | **4** |
| `W-C4-01` | 7 | 6 |
| validate | 0 error / 57 warning | **0 error / 11 warning** |

⚠️ **不违反 B2-fix**：SRT 时间戳**仍不参与任何校验判定**（`W-*`/`E-*` 一条都没碰），
只决定字幕的显示区间。对齐漂移本身仍是缺陷（`M-1d` 待决），此处只是让**字幕不再受害于它**。
