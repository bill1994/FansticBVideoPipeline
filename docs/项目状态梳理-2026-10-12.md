### 2.2 关键设计结论速览

- **自动化边界**：半自动。AI 起草 storyboard → 人在 storyboard 环节审阅 → Remotion Studio 迭代 → 渲染。
- **storyboard 载体**：`storyboard.json` 唯一真源 + HTML 编辑页，导出写回 json。
- **阈值策略**：两道闸串联（闸1 路由 / 闸2 审核强度），动态阈值 T，安全阀「库不适配整批转 custom」。
- **模板库**：双轴 `family × scope` + 命名空间版本化 `family/subtype@version`，12 个 family / 6 个 scope。
- **遮挡规避**：遮挡容忍度是**向量而非标量**——人脸 0% / 手持物 ≤20% / B-roll 主体 ≤30% / 其余无限。
- **渲染技术栈**：准入标准是「帧确定性可控」，A（官方包）/B（官方范式）/C（社区库+自建适配器，p5.js）三档。
- **版本锚定**：锁 `remotion@4.0.534`（`--save-exact`，禁 `^`），Node 22.19+/24+，渲染必须 `--gl=angle`。
- **工程结构**：`jobs/<jobId>/00-input → 06-review` 阶段目录，每级不可变快照，禁跨级引用。

## 4. 下一步优先任务与顺序

```
① 修正文档一致性（10 分钟）→ ② git init（5 分钟）
        ↓
③ 生成 Spec（合并四张清单）—— 当前最高优先级
        ↓
④ 按阶段切 5 个 Skill（align / perceive / storyboard / validate / render）
        ↓
⑤ 按 Spec 实现：校验器 14 项 + 模板库骨架 + 感知管线
        ↓
⑥ 实测闭环：C2-2 阈值校准 → 首次渲染基准（10 分钟成片墙钟 + CPU 峰值）
```

### 优先级排序理由

- **①② 必须先做**：文档内部自相矛盾会污染 Spec；无 git 则实现期无法回滚。
- **③ Spec 是唯一瓶颈**：所有后续动作（Skill、实现）都依赖它，且四张清单已备齐，是「抄作业」而非「重新设计」，性价比最高。
- **④⑤ 可并行推进**：Skill 是行为契约、实现是代码，两者共用同一份 Spec，可交替验证。
- **⑥ 必须在实现骨架跑通后**：阈值和基准都需要真实数据，早做无意义。
