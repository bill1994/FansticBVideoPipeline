# docs/reviews · 索引与分类约定

> 这个目录混装四种性质完全不同的文档，历史命名不统一（「审核」与「审计」混用）。
> 引用时请先看类型列，别把「调研」当「判定」。

## 四类文档

| 类型 | 判定性质 | 回答的问题 | 典型标志 |
|---|---|---|---|
| **评审** review | ✅ 有 | 这份文档/方案能不能作为上游契约 | 「总判定 / 通过·不通过」 |
| **审计** audit | ✅ 有 | 文档声明与代码实况是否一致 | 「只读审计 / 当场复算」 |
| **调研** research | ❌ 无 | 外部项目怎么做、该选哪个技术 | 「对标 / 选型 / 来源清单」 |
| **实测** test | ❌ 无 | 真素材上测出了什么 | 「现象 / 根因 / 复现步骤」 |

⚠️ **只有前两类是「审核结论」**。引用「某次审核说了什么」时，先确认它不是调研。

## 不属于本目录的两类「审核」

- **结构化人工放行**：`jobs/<jobId>/06-review/confirmed.json`
  （`confirmedBy` / `confirmedAt` / `acknowledgedFullscreen` / `overrides`）。
  ⚠️ `jobs/*` 被 `.gitignore` 忽略 ⇒ **不跨机同步**，且 `storyboard` 目前不消费它。
- **裁决记录**：`docs/decisions/OPEN-DECISIONS.md`。它是**唯一裁决真源**，本目录的任何结论与之冲突时以它为准。

## 新增文档时

1. 文件名带日期 + 能表明类型的词（评审 / 审计 / 调研 / 实测）。
2. 正文头部写清「对象 / 方式 / 性质（只读？是否改代码？）」。
3. 若产生**可执行结论**，同步更新 `2026-10-19-审核结论汇总与后续计划.md` 的未消化清单。
