## 三、问题清单

### A. 管线中断点

**A1. 非语音素材会让 `align` 停在半路，且残留未记录的中间文件**
`whisper` 对 440Hz 正弦音输出 `(字幕:J Chong)`，无 token → `words=[]` →
`✗ 对齐结果为空 —— 没有词级时间戳，pipeline 无法启动`，**退出码 2**。
`01-align/` 留下 `audio.wav` + `whisper-ojf.json`，**没有 `words.json` / `align-report.json`**。
⚠️ 与 SKILL 声明的退出码不符：`align/SKILL.md` 写「门控未过 → 1」「音频抽取失败 → 4」，实际是 **2**。

**A2. 🔴 对齐门控失败后，人工放行回路是死的**
照 CLI 提示写了 `06-review/confirmed.json`（`stage:"alignment"`、`overrides:[]`）后重跑 `storyboard`，
**仍然 exit 1，报错一模一样**。
根因：`readConfirmed()` 全库唯一消费者是 `renderGate()`（只管 fullscreen）；
`storyboard.ts` 只读 `draft.meta.confirmedBy`，**从不读 `confirmed.json`**。
⇒ 任何 `gatePassed=false` 的素材**无法进入 storyboard**，只能改 align 产物或伪造 `gatePassed`。

**A3. 渲染失败拿不到退出码 4**
`exit-code.ts` 定义 `RENDER_FAILED: 4`，`grep` 全库**零消费**；`cli.ts` 的 render 分支恒 `return EXIT.OK`，
异常落 `catch` → `EXIT.INTERNAL = 6`。监控按文档判「4 = 渲染失败」永远等不到。

### B. 数据流异常

**B1. `decision` 全组零消费**（见 §2.2）。`storyboard/SKILL.md` 用 60 行讲两道闸与产路地板，产物里写了，下游没人看。
**B2. `meta.alignmentConfidence` 零消费**。
**B3. `textSource` 零消费**。
**B4. `subjectBox` 零消费，且提示让人补一个结构上不存在的字段** —— `W-F6-01` 说「在 confirmed.json 里补 subjectBox 覆盖」，而 `ConfirmedRecord` 无此字段。
**B5. `confirmed.json.stage` 不参与判定** —— 实测：`stage:"alignment"` + 正确的 `acknowledgedFullscreen` ⇒ **render 闸放行**。
**B6. `overrides` 零消费** —— 校验不过后让人写「改了什么」，没有任何代码读它。
**B7. 素材分辨率不进契约** —— `SourceManifest` 只有 `video/srt/fps/durationInFrames`；
`Root.tsx:51-52` 把 `width=1920 height=1080` **写死**，`calculateMetadata` 只覆盖 fps 与时长。
实测 640×360 素材 → 成片 **1920×1080**（画面被放大）。竖屏素材当前无路可走。

### C. 产物缺失 / 冗余

**C1. `05-render/` 缺两个文档指定产物** —— SKILL 要求「Remotion 工程 + `out.mp4` + `render.log`」，
实际只有 `out.mp4` + `render-props.json`（无工程目录、无渲染日志；墙钟与 CPU 峰值只在控制台打印）。
**C2. `02-perceive/` 与 SKILL 清单不符** —— SKILL 列 6 项（`frames/`、`subject.json`、`handheld.json`、`broll.json`、`regions.json`、`shots.json`），
实际 2 项（`shots.json`、`regions.json`）。**三类区域合并进 `regions[].kind`，内容没缺；但抽帧图不落盘**。
**C3. 死代码**：`validate/context.ts:58` 的 `loadOrDefault()` 零调用。
**C4. 中间产物未登记**：`audio.wav`、`whisper-ojf.json` 不在任何阶段产物清单里。

### D. SKILL 与实现分叉

**D1. 🔴 `align/SKILL.md:31` 仍写「只取 SRT 的文本，**不信任 SRT 的时间戳**」**
—— 这是 2026-10-19 刚刚撤回的假铁律，14 处修正里**漏了这一处**。
SKILL 是模型执行契约，模型读它会照做（现已与 `align.ts` 的实现相反）。

**D2. `storyboard/SKILL.md:188` 仍教模型用 `handoffIn`** —— 该字段已在问题 9 审计中删除。

**D3. 退出码表三处与代码不符**
`align`（门控 1 / 抽音 4）、`perceive`（检测失败 4）、`render`（失败 4）—— 实际只有 `1/2/6` 被用到。

**D4. 决策字段形状不一致**
SKILL 说「每个 item 带 4 个决策字段（`sim_max`/`confidence`/`routing`/`review`）」；
起草稿里它们是**顶层**，产物里变成 `item.decision.{...}` 嵌套对象。两套形状，SKILL 未说明。

### E. 🔴 占位素材覆盖不到的环节（不代表无 bug，代表本轮没证伪）

| 环节 | 为什么覆盖不到 |
|---|---|
| **align 正常路径**（词级时间戳） | 需要真人语音；正弦音出不了词（A1） |
| **多 shot 切分** | 两段纯色硬切，`scdet` **检出 0 个切点** → 1 个 shot（预期 ≥2） |

| **真实视频解码的边界** | 只验了 120 帧小文件；2836 帧崩溃那类问题不会在此暴露 |
| **`--force` 重跑与快照作废** | 本轮未触发（`words.json` 与 `align-report.json` 必须同时存在才跳过，失败态不会被误跳过 ✅） |
