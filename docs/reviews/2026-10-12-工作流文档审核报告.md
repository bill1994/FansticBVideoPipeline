## 三、阻断项（必须修，共 3 项）

### B-1 已成型决策缺编号，导致无法被引用

§1 已决表中有三行编号为「—」：

| 无编号决策 | 正文位置 | 实质内容 |
|-----------|---------|---------|
| 阈值策略 | §2 全文 | 两道闸串联、动态 T、配额锚 70-90%、硬边界 0.50/0.80、安全阀 |
| 模板库分类结构 | §3 全文 | 双轴 12 family + 6 scope + 强制契约 + 命名空间版本化 |
| 落地路线 | §1 表格行 | 方案 C（混合）：video-shotcraft shot 库 + workbench |

这三项都有完整结论，但**没有决策号**。后果：
- 后续 Spec 无法写「依据 B5 阈值策略」
- 讨论时无法精确指代（「上次那个配额锚」而不是「B5」）
- 顶部「分支 A/B 已封口」这句话覆盖不全 —— A 分支只有 A1，B 分支 B1-B4，这三块无主决策落在 A/B 之外

**修法**：补为 B5（阈值策略）、B6（模板库双轴）、R1（落地路线）。

### B-2 C2 依赖的词级时间戳在 B3 中不存在（跨分支硬矛盾）

- C2 原文：「锚点粒度：cue 级为主 + **词级可选（词级来自 Whisper 逐词时间戳）**」
- B3 原文：①场景切分+每 1.5s 抽帧 ②多模态模型结构化打标 ③`silencedetect` 抓停顿做锚点 ④汇成 `timeline.json`

B3 的四步里**没有任何 ASR / Whisper 环节**。也就是说 C2 承诺的「词级可选」在当前感知管线中无数据来源。
这不是"以后补"的问题 —— 它改变了架构：B3 从「视觉感知管线」变成「视觉+语音双模态管线」，成本、耗时、失败模式全部不同。

**修法**：二选一
- (a) 在 B3 追加第 5 步：Whisper 逐词对齐（SRT 已有字幕，Whisper 只需出时间戳，可强制对齐到 SRT 文本，代价较低）
- (b) 砍掉 C2 的词级粒度，明确「cue 级 + 段级」两种粒度，词级列为 v2

**建议 (a)**：本项目输入已带 SRT，Whisper 的 `initial_prompt`/强制对齐模式能低成本复用 SRT 文本，且词级锚点是「动画卡在词上」这个手感的唯一来源，砍掉会削弱产品说服力。

### B-3 §4 C1 的 JSON 示例使用被 C2 作废的语法

C1 示例：
```json
{ "tracks": [ { "id": "typo-a", "layer": 60, "items": [ { "span": "L2→L3", ... } ] } ] }
```
C2 已决：「真相层 = 帧，落盘 `{fromFrame, durationInFrames}`」「锚点用完即弃」。

示例里的 `span: "L2→L3"`（语言段落跨度）是 C2 之前的旧语法。两个后果：
- 读者/后续开发者照抄示例 → 直接实现出被否决的模型
- 文档内部两个权威源打架，Phase 1.5 生成 Spec 时会以示例为准还是以决策为准？不确定

**修法**：示例重写为烘焙后形态，并把作者语法写成注释或旁注。

```json
{
  "tracks": [{
    "id": "typo-a", "layer": 60,
    "items": [{
      "_author": { "anchor": "cue:12", "offset": "-8f" },   // 仅编辑期可见，烘焙后剥离
      "fromFrame": 372, "durationInFrames": 96,
      "motion": "typography/kinetic-line"
    }]
  }]
}
```

## 四、非阻断问题（7 项）

### N-1 layer 字段有两个权威来源，未定义优先级
§3 模板强制契约含 `layer`（模板自带层级）；C1 示例中 `layer` 挂在 track 上。二者冲突时谁赢？
**建议**：模板的 layer 只作为默认值，track 声明覆盖模板默认值；模板层不得反向约束 track。

### N-2 C1 遗留的「互斥冲突检测」没有落到任何分支的验收清单
C1 自己写了代价：「互斥不再由结构保证 → 需在校验期/运行时查同 exclusive 组冲突」。
但 §6 盲区清单和 §8 下一步都没有把这条列为待落地项。**校验项遗漏 = 交付后必炸**。
建议：把 `exclusive 冲突检测` 显式写入 F 分支的校验器验收清单。

### N-3 阈值三字段没有合法组合空间
已决：`routing: template|custom`（由闸1 的 `sim_max ≥ T` 决定）、`review: auto|alternatives|must_review`（由闸2 的 `confidence` 决定）、`custom 必审`（来自 B4）。
三者的交叉组合未定义，例如：
- `sim_max` 高（走库）+ `confidence` 低（挂备选）→ 合理
- `sim_max` 低（转 custom）+ `confidence` 高 → 是 `auto` 还是 `must_review`？B4 说 custom 必审，闸2 说只调制强度不改产路 —— **这里两条已决决策直接对撞**

**建议**：明确定义 2×3 组合矩阵，把 B4 的「custom 必审」降级为「custom 的 review 下限 = must_review」，消除冲突。

### N-4 动态阈值 T 的最小样本量未定义
§2 用了「分数排序后最大间隙（elbow）」求 T，但 elbow 需要足够样本才有意义。文档只处理了「样本少 → 固定 T=0.65」，没定义多少才算「够」。
建议：补 `N < 8 → 固定 T=0.65`，`N ≥ 8 → elbow`。

### N-5 §5 调研结论没有落成「采纳 / 不采纳」决策表
§5 给了 8 个可抄机制 + 5 个根本差异，读完知道边界在哪，但**不知道我们采用哪几个**。落地路线说用 video-shotcraft 的 shot 库 + workbench，却没写采纳边界（用哪几类卡？workbench 是 fork 还是自研？）。
**建议**：§5 后追加一张采纳表：`机制 → 采纳/借鉴/不做 → 归属分支`。

### N-6 §6 盲区清单缺 5 项

| 缺失盲区 | 风险 |
|---------|------|
| 抽帧密度 1.5s 与短 motion 的冲突 | 短于 1.5s 的槽位没有任何视觉证据，模型只能猜 |
| 输入 SRT 与拼接后视频的时间轴是否已对齐 | §0 说视频是「已粗剪拼接」，拼接会产生时间轴偏移；若 SRT 未同步，感知全错。这是入口级风险，目前**完全没提** |
| 音频处理是否在范围内 | §5 引用了 dead air / audio-bed-check，但正文从头到尾没定义本项目是否做音频 QC |
| 渲染成本量化目标 | F 分支只有机制参照（lock.json），没有数字目标（单片上限 / 渲染时长上限） |
| 返修回路的回退方案 | 全部分支封口后若 D 走不通，没有 Plan B |

### N-7 §7 术语表混入会话元信息，且缺外部概念
- 「grill-me = 本会话采用的逐分支追问式设计评审方法」属于**会话元信息**，不该进项目术语表（换个人接手就失效）
- 缺失且正文高频出现的外部概念：`exclusive`、`slot`、`lock.json`、`workbench`、`ClipCard`、`safe zone`、`dead air`、`beatF`、`mulberry32`
