# 05 · 校验体系

真源：[src/validate/index.ts](file:///g:/VideoPipeline/src/validate/index.ts) 的
`DOCUMENTED_CHECK_ITEMS` 与 `EXTRA_CHECKS`；错误码表在
[src/core/errors.ts](file:///g:/VideoPipeline/src/core/errors.ts)。

## 1. 组织方式

- **构建期校验 = 纯函数 JSON→JSON**：不渲染、逐项独立判定、不剔除非法 item
  （剔除会让报告随执行顺序变化并吞掉其他项的问题）。
- **结构性错误不降级**：`assertStructuralIntegrity`（如 `handoffTo` 指向不存在的 track）
  抛 `ConfigError` → 退出码 2 —— 「配置错」不能伪装成「内容没做好」。
- **有 error 必须停**（退出码 1），warning 不拦。
- **渲染期兜底另算**：字体未加载 / Canvas 未挂载 / GPU 上下文失败只能在真实渲染时暴露，
  由 render 阶段产出 `stage:"render"` 条目，不属于这 18 项。
- **活清单纪律**：增补校验项须先改 `docs/decisions/OPEN-DECISIONS.md`，不得只改代码。

## 3. 清单外的 extra（执行但不计入 `checked`）

| 码 | 内容 | 为什么不进清单 |
|----|------|----------------|
| `W-D3-01` | storyboard 含 fullscreen 模板 → 预告需人工确认 | 确认记录产在 `06-review`，构建期读不到（D3-a 裁决：确认落在 render 启动闸）—— 准入判据①不满足 |
| `W-F6-01` | 区域 `lowConfidence` 主体未确 → 提示人工兜底 | 只是提示，不属「渲染前就该拦」—— 准入判据③不满足 |

`summary.checked`（18）+ `summary.extra`（2）相加才是本次执行的全貌。

**清单准入规则**：输入在本阶段可读 / 纯结构化判定 / 渲染前就该阻断 —— 三条全中才进；
**例外只应该有 D3 这一条**。

## 4. 人工审核队列（reviewQueue）

P2 裁决（2026-10-19）：产路地板把 `custom` 抬到 `must_review` 之后，此前没有任何消费者。
`runValidation` 末尾把 `decision.review === 'must_review'` 的条目收进
`report.reviewQueue`（`{ref, motion}[]`），作为「该看哪几条」的清单落地。

⚠️ 它**不是校验项**：不进 `checked`、不影响 `ok`、不产 `ReportItem`。

## 5. 渲染启动闸（validate 之外的拦截面）

render 阶段另有四道启动闸（[stages/render.ts](file:///g:/VideoPipeline/src/stages/render.ts)）：

1. `04-validate/validate-report.json` 存在且 `ok === true`；
2. fullscreen 场景要求 `06-review/confirmed.json` 含 `stage:"render"` + `acknowledgedFullscreen`；
3. Remotion 版本锚定自检（`assertVersionPinned`，锁 `4.0.534` 禁 `^`）；
4. storyboard `meta.fps` 与素材 fps 漂移检查。
