# 03 · 数据契约与目录产物

真源是 [src/core/types.ts](file:///g:/VideoPipeline/src/core/types.ts)（冲突时以
`docs/decisions/OPEN-DECISIONS.md` 为准）。本文档按 job 目录顺序串起所有产物。

## 1. `00-input/` —— 素材清单

```json
// source.json（SourceManifest）
{
  "video": "raw.mp4",            // 已粗剪拼接、无文字无特效
  "srt": "raw.srt",              // 文本与句子时间的权威来源
  "fps": 30,
  "durationInFrames": 900,       // 成片总帧数 = Composition 时长
  "width": 1920, "height": 1080  // 可选；省略时 render 用 ffprobe 读，兜底 1920×1080
}
```

要点：`width`/`height` 必须**同时填或同时省略**（只填一个 → ConfigError 退出码 2，
P4 裁决）。

## 2. `01-align/` —— 强制对齐产物

### `words.json`（`AlignWords`）

```ts
interface AlignWords {
  fps: number;
  words: WordTimestamp[];  // 词级时间戳
  cues: Cue[];             // 字幕 cue（并入同一份时间数据，不新增产物文件）
}

interface WordTimestamp {
  index: number;
  word: string;
  startFrame: number;
  endFrame: number;
  confidence: number;      // 0–1 词级对齐置信度
}

interface Cue {
  index: number;
  fromFrame: number;       // 首词 startFrame
  toFrame: number;         // 末词 endFrame（含端点）
  text: string;
  srtFromSec?: number;     // SRT 原始秒 —— 字幕显示时序的权威（C2-6），不参与校验判定
  srtToSec?: number;
}
```

### `align-report.json`（`AlignReport`）

| 字段 | 含义 |
|------|------|
| `mode` | `'aligned'`（正常测量）或 `'no-subtitle'`（M-1g 显式声明无字幕：words/cues 为空数组、只能用 `abs:` 锚点）—— 空产物与异常产物靠它区分 |
| `meanConfidence` | 整体均值置信度，门控项（阈值 `0.60` 🔴待校准） |
| `lowConfidenceRatio` | 低置信词占比，门控项（阈值 `≤0.30` 🔴待校准） |
| `alignedRatio` | SRT 词对上 whisper token 的比例，门控项（阈值 `≥0.80` 🔴待校准）—— `meanConfidence` 测不到「SRT 与音频是否对得上」（M-1c） |
| `gatePassed` | 门控是否通过；未过必须阻断（C2-2/C2-4），人工写 `confirmed.json` 后放行 |
| `lowConfidenceWords` | 低置信词序号清单，供人工复核 |
| `textSource` | `'srt' \| 'whisper-asr'` —— 文本权威审计记录（M-1c，当前无代码消费者，定位是审计字段） |
| `silentWordRatio` | 词落在静音段内的时长占比（M-1d）。**`null` ≠ `0`**：`null`=没测，`0`=测了且正常。超过 `SILENCE.wordRatioWarnMax`（2%）告警、不阻断（阻断线未校准） |
| `reweighedCues` | 按 SRT 窗口重铺过词时的 cue 数（M-1f） |
| `thresholds` | 实际使用的四个阈值（含 M-1d 告警线 `silentWordRatioWarnMax`），便于事后追溯 |

## 3. `02-perceive/` —— 感知产物

### `shots.json` / `regions.json`（`PerceiveResult`）

```ts
interface Shot {
  id: string;
  fromFrame: number;
  durationInFrames: number;
  safeArea: Footprint | null;  // 主体 bbox 上部（比例 0.6 🔴占位），按 shot 取并集
                               // null = 主体不在场 → 全画面可行域
  subjectBox?: Footprint;
  lowConfidence?: boolean;     // 不阻断，validate 出 W-F6-01
}

interface PerceiveRegion {
  id: string;
  kind: 'face' | 'handheld' | 'broll';  // 三通道，预算彼此独立
  shotId: string;
  fromFrame: number;
  durationInFrames: number;
  box: Footprint;              // 人脸 / 手持物外扩框 / B-roll 显著性框
  lowConfidence?: boolean;
}
```

遮挡预算（D2）：`face: 0%` / `handheld: ≤20%` / `broll: ≤30%` —— 判定的是
「从各级区域各拿了多少额度」，不是「有没有相交」。

## 4. `03-storyboard/` —— 起草与烘焙

### `draft.json`（输入，模型/人工起草）

模型只做三件事：**挑模板（motion id）、填文字（params）、写锚点（`_author`）**。
禁写坐标/帧数/颜色/CSS。

### `storyboard.json`（`Storyboard`，烘焙后产物）

```ts
interface Storyboard {
  meta: {
    fps: number;                  // 顶层固化：改 fps 会让帧号语义漂移 → 必须重新烘焙
    anchorMode: 'word' | 'cue';   // cue 是「人工签署的例外通道」，不是降级兜底（C2-4）
    alignmentConfidence: number;  // 来自 01-align
    confirmedBy?: string; confirmedAt?: string;
  };
  tracks: StoryboardTrack[];
  noMotionRanges: NoMotionRange[]; // 禁配段：任何 motion 与之相交 → E-E5-01
}

interface StoryboardTrack {
  id: string;
  layer: number;               // z 序（越大越上），与 track 正交（C1）
  handoffTo?: string | null;   // track 级接力声明，禁止放 item 层（C5）
  items: StoryboardItem[];     // 轨内 items 允许重叠 —— 硬约束 3 的要求
}

interface StoryboardItem {
  _author?: AuthorAnchor;      // 烘焙后剥离
  fromFrame: number;           // ← 帧是真相：落盘只有这两个字段
  durationInFrames: number;
  motion: string;              // 'family/subtype@version'
  footprint: Footprint;        // [x,y,w,h] 归一化 0–1，取全动画期最大包围盒
  exclusive?: string;          // 互斥组名；默认不互斥
  footprintAnimates?: boolean; // true → 相交检测由 error 降 warning（C3）
  params?: Record<string, unknown>;   // 按 paramsSchema 校验（#16）
  carrier?: CarrierRef;        // 载体退让声明（D4-t2，逐 item）
  decision?: ScheduleDecision; // {sim_max, confidence, routing, review}
}
```

### `bake-report.json`（`BakeReport`）

锚点解析记录，供 validate 只读消费（校验 #1 需要帧↔词映射）：

```ts
interface BakeRecord {
  trackId: string;
  itemIndex: number;
  anchor: string;        // 'word:37' / 'cue:12' / 'abs:240'
  offset: string;        // '-8f'（负=抢拍，合法）
  wordIndex: number;     // cue:/abs: 锚点为 -1
  wordStartFrame: number; wordEndFrame: number;
  cueIndex: number;      // word:/abs: 锚点为 -1
  fromFrame: number;
}
```

### `pacing.json`（`RhythmTable`，P1 新增 2026-10-20）

节奏表：判断每条 cue 要不要配 motion、配什么。**全部判据都是词表/正则/字数比较**
（`core/rhythm.ts` + `rhythm-rules.ts`），不调用语言模型、不读时钟或随机数 ——
同一份 SRT 必须产出同一份节奏表。

```ts
interface RhythmTable {
  meta: { fps: number; mode: 'aligned' | 'no-subtitle'; version: string };
  cues: RhythmCue[];
}

interface RhythmCue {
  cueIndex: number;
  fromFrame: number;        // ⚠️ cue 区间快照，非独立真源，禁止二次推导
  durationInFrames: number;
  decide: 'motion' | 'none';
  motion?: string;          // 仅 decide==='motion' 时存在
  reason: string;           // 人可读的判断依据
  signal: RhythmSignal[];   // 命中的走势信号
  skipped?: 'too-short' | 'no-template-fits';
}

type RhythmSignal =
  | 'turn' | 'contrast' | 'enum' | 'question' | 'number'
  | 'short-after-long' | 'closing' | 'definition' | 'cause-effect' | 'repetition';
```

时长门槛：cue 时长 `< minCueFramesForMotion`（当前 10 帧 🔴占位）→ `skipped: 'too-short'`。
字幕模板不受此门槛约束（每条 cue 恒有一条字幕 item）。

## 5. `04-validate/` —— 校验报告

```ts
interface ValidateReport {
  jobId: string;
  ok: boolean;               // 有 error 即 false → 阻断渲染
  summary: {
    checked: number;         // 18 项清单内的执行计数
    error: number;           // 注意：字段名单数
    warning: number;
    extra: string[];         // 清单外执行的规则码清单，如 ["W-D3-01","W-F6-01"]
  };
  items: ReportItem[];       // 逐条目：check/code/level/frames/message/hint/targets/source/stage
  reviewQueue?: { ref: string; motion: string }[];  // decision.review==='must_review' 的人工审核队列（P2）
}
```

真实样例见 [examples/demo/04-validate/validate-report.json](file:///g:/VideoPipeline/examples/demo/04-validate/validate-report.json)：
`{ ok: true, summary: { checked: 18, error: 0, warning: 2, extra: ["W-D3-01","W-F6-01"] } }`。
`checked` 只数清单内 18 项，不含 `extra` —— 两者相加才是本次执行的全貌。

## 6. `05-render/` —— 渲染产物

### `render-props.json`

Remotion `<Composition>` 的 input props（`RenderProps`）：

| 字段 | 含义 |
|------|------|
| `videoPath` / `hasVideo` | 实拍视频路径；无视频时走 `carrier-synth` 影子轨 |
| `storyboard` | 烘焙后的 storyboard |
| `stacks` | **C6 双栈划分结果**：背景链（载体类串联）与叠加栈（并列） |
| `carrierTracks` | 合并后的载体轨时间窗口（`composeCarrierTimeline`） |
| `caption` | 字幕数据（`toCaptionData`，来自 SRT，文本不经 params） |
| `templates` | 模板声明（含 textMetrics / spec） |

### `render-report.json`

渲染报告：墙钟时长、CPU 峰值（`cpuPeakPercent` 写 `null` 表示未采集 ——
`execFileSync` 不暴露子进程 rusage，诚实标注而非编 0）、尺寸来源、人工改动留痕。

### `render-report.json.qa`（P0-2，2026-10-22）

渲染完成后对成片做一次**媒体 QA**（真源 `src/core/media-qa.ts`）：

| 字段 | 含义 |
|------|------|
| `ok` | `errors.length === 0`；**不阻断**渲染，只是报告 |
| `errors` | 解码失败 / 时长与 `durationInFrames/fps` 明显不符（容差 `max(0.15, 2/fps)`） |
| `warnings` | 黑场（`blackdetect`）/ 静帧（`freezedetect`）/ 音频静音或近满刻度 / 联系表失败 |
| `unavailable` | ffmpeg / ffprobe 不可用（判据缺失，**不伪装成通过**） |
| `actualDurationSec` / `expectedDurationSec` / `durationDeltaSec` / `toleranceSec` | 时长对账 |
| `black` / `freeze` | `{segments:[{start,end,duration}], openStart}`；`openStart` 是未闭合到片尾的那一段 |
| `audio` | `{meanDb,maxDb}`；无音频流时为 `null`（不是 0） |
| `contactSheet` | `contact-sheet.jpg` 文件名（未产出为 `null`） |

`contact-sheet.jpg` 用 9 个等距帧拼成 3×3，供人工/多模态模型快速看全片。
Windows 上 ffmpeg shim 无法被 Node spawn 时，用 `FFMPEG_BIN` / `FFPROBE_BIN`
指向真实 exe；否则 QA 只记 `unavailable`，不阻断。

## 7. `06-review/` —— 人工确认

```ts
// confirmed.json（多条记录）
{ "stage": "alignment" | "render", "acknowledgedFullscreen": boolean, ... }
```

两个消费点：

1. **align 门控未过** → 人工确认后写 `stage:"alignment"`，storyboard 阶段
   `lookupConfirmed` 查到才放行（降级到 cue 级时 `meta.anchorMode` 必须标 `'cue'`）。
2. **fullscreen 放行**（D3-a 裁决）：确认落在 render 启动闸 ——
   `stage:"render"` + `acknowledgedFullscreen:true`。构建期只出 `W-D3-01` 预告
   （构建期读不到 06-review，这是「谁有资格拦」的问题）。

## 8. 数据流总图

```
source.json ─┬─ align ──► words.json ──────────┐
             │            align-report.json ──┤
             └─ perceive ─► shots.json ───────┼─► storyboard ─► storyboard.json ─┐
                          regions.json ───────┘       ▲    bake-report.json       ├─► validate ─► validate-report.json ─► render ─► render-props.json ─► 成片
                                    draft.json ───────┘    pacing.json ────────────┘                 │
                                                                                                    └─ 06-review/confirmed.json（门控放行 / fullscreen 放行）
```

不可变性约束（`io.ts`）：每个阶段只能写**自己**的目录；写上游即抛错；
`--force` 是唯一的显式重跑通道。
