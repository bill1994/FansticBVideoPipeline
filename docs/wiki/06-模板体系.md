## 1. 双轴契约：family × scope

### 轴 A｜family（命名空间，12 类，可无限扩）

`caption` · `typography` · `data` · `annotation` · `carrier` · `brand` · `ambience` ·
`cinematic` · `transition` · `rhythm` · `sfx` · `custom`

### 轴 B｜scope（枚举，固定 6 值，**不可扩**）

| scope | 栈归属 | 语义 |
|-------|--------|------|
| `under-subject` | 叠加栈 | 压在主体下层 |
| `overlay-safe` | 叠加栈 | 安全区内叠加 |
| `anchored` | 叠加栈 | 锚定主体 |
| `fullscreen` | 叠加栈 | 全屏（需 render 级人工确认） |
| `subject-transform` | **背景链** | 对主体/视频做变换（scale/crop） |
| `footage-transform` | **背景链** | 对素材整体做变换 |

scope 天然二分（`CARRIER_SCOPES` vs `OVERLAY_SCOPES`）同时支撑两件事：

- **C4 主从放行**：`isMasterSlavePair(a, b)` = 载体 × 叠加的跨类组合天然主从，
  相交放行。走枚举自动推导，**不做字符串白名单** —— 白名单会随命名空间无限膨胀，
  新模板需零维护。
- **C6 双栈分离**：渲染期按 scope 拆背景链（串联）与叠加栈（并列），混栈即语义倒置。

## 2. 模板声明契约（`TemplateDeclaration`）

```ts
interface TemplateDeclaration {
  id: string;                  // 'family/subtype@version'，semver 版本锁定
  family: Family;
  subtype: string;
  version: string;
  scope: Scope;
  layer: number;               // 默认 z 序；track 声明可覆盖（N-1）
  occludesSubject: boolean;
  paramsSchema: Record<string, string>;  // 模型只填表不写代码
  requiredParams?: string[];   // P1：省略 = 全部可选（paramsSchema 装不下 required）
  status: 'core' | 'experimental' | 'custom';
  footprint: Footprint;        // 默认占位矩形；item 可覆盖
  minVisibleInFrames: number;  // 校验 #6 用
  textMetrics?: TextMetrics;   // 校验 #17 字号真源（省略=无可测文本）
  spec?: MotionSpec;           // 仅 custom/* 由 spec 派生时存在
}
```

设计要点：

- **`paramsSchema` 与 `requiredParams` 正交**：键存在性查前者，必填语义查后者。
  刻意不把值改成 `{type, required?, default?}` —— `default` 是渲染期的事，
  塞进校验层属职责混淆。
- **`textMetrics` 必须进契约而不是让校验器另写一份字号表**：字号若硬编码在组件 style 里，
  校验器拿不到；另写一份则改组件字号时校验器不跟着变 → 溢出判定静默失准。
  `charWidthEm` 默认按 CJK 全角 1.0em（本项目素材为纯中文口播）。
- **字幕文本与颜色都不经 params**：`caption/karaoke-word` 刻意不声明 `text`
  （来自 SRT）也不声明颜色（已摘除 `highlightColor`）—— 高亮色由渲染期按
  **命名令牌**（`'brand'`/`'accent'`）解析。留着任何一个都等于让模型能硬写文本或色值。

## 3. 注册表（registry.ts）

| 函数 | 语义 |
|------|------|
| `registerTemplate(decl, source?)` | id 查重；**禁止覆盖内置模板**；记录来源（builtin / spec / 测试） |
| `getTemplate(id)` / `hasTemplate(id)` | 查询；未注册即报错 |
| `assertRegistryValid()` | 启动期契约校验，CLI `main()` 第一步 |

**装载时序**（[cli.ts](file:///g:/VideoPipeline/src/cli.ts) `main()`）：
`assertRegistryValid()` → `loadSpecsFromDisk()`（装载 `templates/specs/*.json` 派生的
`custom/*`）→ 才分发阶段。顺序错了 custom 模板会被判「未注册」。

### spec 结构（`MotionSpec`，契约在 [core/spec.ts](file:///g:/VideoPipeline/src/core/spec.ts)，~865 行）

```jsonc
{
  "specVersion": 1,
  "id": "custom/fade-up@1.0",
  "layer": 60,
  "footprint": [0.15, 0.62, 0.7, 0.18],   // 归一化 [x,y,w,h]
  "minVisibleInFrames": 24,
  "occludesSubject": false,
  "elements": [                            // 图元声明
    { "type": "text", "slot": "main", "content": "excerpt",
      "sizePx": 48, "weight": 700, "align": "left", "paddingPx": 24 }
  ],
  "tracks": [                              // 属性轨道 + 关键帧
    { "element": 0, "property": "opacity",
      "keys": [ { "t": "8f", "v": 0, "ease": "out" },
                { "t": "14f", "v": 1, "ease": "out" } ] }
  ]
}
```

- **时间语法**（[spec-time.ts](file:///g:/VideoPipeline/src/core/spec-time.ts)）：
  绝对帧 `8f` / 秒 `Ns` / 相对比例。fade-up 的 `_note` 解释了为什么用绝对帧而不用
  `0→1` 比例 —— 比例会让整句 4 秒都在缓慢滑动，长句尤其拖沓；绝对帧保证入场快速完成，
  上界受 `minVisibleInFrames` 约束。
- **`validateMotionSpec`**：元素/轨道/关键帧规则、token 白名单、参数校验，错误逐条收集。
- **`deriveDeclaration`**：spec → `TemplateDeclaration`，走注册表注册，
  之后 `custom/*@1.0` 与内置模板在校验/烘焙/渲染眼里无差别。
- **渲染链**：`getTemplateComponent` 对 `custom/*` 返回 `SpecRenderer` →
  按 `frame` 求值各轨道关键帧（spec-time 同一实现）→ [spec-style.ts](file:///g:/VideoPipeline/src/remotion/templates/spec-style.ts)
  合成 CSS → 渲染文本与装饰图元。

## 6. 模板组件渲染契约（`TemplateProps`）

```ts
interface TemplateProps {
  frame: number;             // 由 MotionItem 下发（全树唯一 useCurrentFrame）
  durationInFrames: number;
  item: StoryboardItem;      // params / footprint / carrier
  caption: CaptionData;      // 字幕文本（SRT 权威）
  children?: ReactNode;
  canvasWidth: number;
}
```

- `footprintStyle`：归一化包围盒 → 绝对定位样式。
- `fitScale` / `fitScaleFor`：文字超宽时等比缩小（与校验 #17 的估算口径互补）。
- 硬约束在组件层同样生效：动画推进只认 `frame` prop；随机性用 `mulberry32`
  （seed 从 item index 派生）；禁 CSS animation / z-index。

## 8. 预览画廊（P0-1，2026-10-21）

在改 motionboard 之前，先看见模板长什么样 —— 不必等一次完整渲染。

```bash
npm run templates:gallery
```

产物在 `out/template-gallery/`（已 gitignore）：

| 文件 | 内容 |
|------|------|
| `gallery.html` | 离线画廊：每卡 3 帧 + scope / footprint / 参数 / 标签 / provenance |
| `images/<slug>-f<frame>.png` | 每个已实现模板 3 张（f6 入场 / f45 中段 / f72 收尾，90 帧 @30fps） |
| `catalog.json` | 目录快照：19 个声明 = 17 已实现 + 2 未实现 |

**目录真源**：[gallery.ts](file:///g:/WorkbuddyProject/VideoPipeline/src/templates/gallery.ts)
—— `buildTemplateCatalog()` 从注册表 + `isImplemented()` 派生，不手抄模板表；
`buildGalleryItem()` 把条目变成单 item 故事板；`renderGalleryHtml()` 是纯函数，离线、无外部资源。
未来 MCP 的 `templates_list` 应直接复用这份目录，而不是另建一份。

**预览合成**：[TemplateGallery.tsx](file:///g:/WorkbuddyProject/VideoPipeline/src/remotion/gallery/TemplateGallery.tsx)
—— 只渲染一个 item，但走 `MotionItem`（与成片同一条主链），因此不会出现「预览好看、成片另一套」。
背景是固定的深色渐变 + 版式网格 + 主体剪影；剪影不是装饰：
`center-emphasis` / `split-frame` 的语义就是「压在人身上 / 把人留在窗口里」，没有主体就预览不出真实形态。
`gallery.html` 已显式注明「合成底板不代表最终素材上的遮挡效果」。

**确定性**：同一份 catalog 两次生成，51 张图里 50 张 SHA-256 完全一致；
`cinematic/punch-in` 的 f72 有 1/255 级 GPU 抖动（mean diff ≈ 5.6e-6，显著像素比 0），
与 EAC 的「GPU shadow dithering」同类，属内容稳定下的像素微差。

**扩模板时**：在 `gallery.ts` 的 `META` 里补 `name / description / tags / params`；
新 spec 会被 `loadSpecsFromDisk()` 自动纳入目录（缺 META 时用 fallback 名称与必填参数占位）。
测试见 [template-gallery.test.ts](file:///g:/WorkbuddyProject/VideoPipeline/tests/template-gallery.test.ts)
（7 项：覆盖性、实现状态、三帧、必填参数、字幕夹具、HTML 离线/转义、slug 安全）。
