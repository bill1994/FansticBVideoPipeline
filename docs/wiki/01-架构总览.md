# 01 · 架构总览

## 1. 项目定位

**Remotion Overlay Pipeline**（`remotion-overlay-pipeline` v0.2.0）解决的是一个与主流
motion-graphic 工具（从零做视频）相反的问题：**在已有实拍视频上叠动效**。
由此带来三件必须自研的事：

1. **不遮挡主体** —— 动效出现时不得压住 presenter 的脸。遮挡容忍度是**向量**：
   人脸 `0%` / 手持物 `≤20%` / B-roll 主体 `≤30%`（见 `src/core/config.ts` 的 `OCCLUSION_BUDGET`）。
2. **可对主体 scale / crop 并置入 graphic 载体** —— 载体模式兼作遮挡冲突时的自动退路。
3. **动画可持续交叉** —— 多轨并行、一段 motion 覆盖多段话，时间重叠是常态而非异常
   （因此 Remotion 的 `<Series>` 被禁用，它结构上无法表达重叠）。

技术栈：TypeScript（ESM）+ Node ≥22.19 + Remotion `4.0.534`（精确锁定）+ React 18 +
onnxruntime-node（跑 YuNet 人脸检测）+ 外部 ffmpeg / whisper.cpp。

## 2. 五阶段管线

```
00-input ──► 01-align ──► 02-perceive ──► 03-storyboard ──► 04-validate ──► 05-render ──► 06-review
  素材        强制对齐       感知与安全区      storyboard 起草     校验（18 项）      渲染出片      人工放行
              ↑ 门控阻断                       ↑ 烘焙锚点→帧      ↑ 有 error 停      ↑ 启动闸
```

| 阶段 | CLI 命令 | 职责 | 何时必须停 |
|------|----------|------|-----------|
| align | `npm run pipeline -- align` | 抽 16kHz 单声道 wav → 强制对齐 → 置信度门控 | 门控不达标必须停，降级必须阻断 |
| perceive | `npm run pipeline -- perceive` | 抽帧、镜头切分、主体检测、安全区与区域预算 | 低置信**不阻断**，走告警 + 人工兜底 |
| storyboard | `npm run pipeline -- storyboard` | 按**词级锚点**起草并烘焙 `storyboard.json` | 安全阀 / fullscreen / custom 不许绕地板 |
| validate | `npm run pipeline -- validate` | 跑构建期校验（18 项，纯 JSON→JSON） | 有 error 必须停，不进渲染 |
| render | `npm run pipeline -- render` | C6 双栈映射 + 本地渲染 | 校验未过 / fps 漂移 / 版本未锁 → 拒绝启动 |

另有 `init`（建 job 骨架）与 `--no-subtitle`（声明无字幕对齐模式，见 `runNoSubtitleAlign`）。

**每一级都是不可变快照，下游不得回写上游。** 返修改第 3 级，第 4/5 级作废重跑。
这一条由 [src/core/io.ts](file:///g:/VideoPipeline/src/core/io.ts) 的
`assertNotWritingUpstream` / `writeStageJson` 在代码层强制。

## 4. 核心设计原则（写在代码里的硬规则）

| 原则 | 落点 |
|------|------|
| **帧是真相** | 落盘只有 `fromFrame + durationInFrames`；模型写锚点 `{anchor:"word:37", offset:"-8f"}`，由 [bake.ts](file:///g:/VideoPipeline/src/core/bake.ts) 一次性烘焙，锚点用完即弃 |
| **负偏移＝抢拍，合法** | 唯一边界：不得早于锚定词所在 cue 的起点（校验 #1，`E-C2-5-01`） |
| **不手算帧** | 模型只挑模板 + 填文字，禁写坐标/帧数/颜色/CSS；字幕文本与颜色都不经 `params` |
| **测量 vs 选择分工** | 逐词时间戳、bbox、显著性属于**测量**（whisper/YuNet/ffmpeg 干）；模板挑选、shot 分类、文案属于**选择**（模型干）。测量误差必须小于容差，故不用多模态大模型做测量 |
| **绝不伪造结果** | 内置后端跑不通（缺模型/缺 ffmpeg）→ 显式报错退出码 2，不产出静默错误数据 |
| **参数逐项校验** | `params` 按 `paramsSchema` 校验（#16）：`E-P1-01` 未知键 / `E-P1-02` 缺必填 / `E-P1-03` 类型不符，三条全 error、不做隐式转换、不剔除非法 item |
| **主从放行走枚举推导** | scope 枚举自动推导主从关系（[types.ts](file:///g:/VideoPipeline/src/templates/types.ts) `isMasterSlavePair`），不做字符串白名单 |
| **不遮挡主体优先** | 安全区判定（D 分支）优先于 exclusive 组判定（C4） |
| **动画推进权属于 frame** | 禁 `Date.now()` / `performance.now()` / `Math.random()`（用 `mulberry32`，seed 从 item index 派生）/ CSS animation / R3F `useFrame`。整棵渲染树只允许 [MotionItem.tsx](file:///g:/VideoPipeline/src/remotion/MotionItem.tsx) 一处 `useCurrentFrame()` |
| **禁显式 z-index** | z 序由 `(layer 升序, trackIndex 升序)` + DOM 嵌套决定 |

## 5. C6 双栈映射（渲染层的核心架构）

模板的 `scope` 把所有动效天然二分成两栈：

```
┌──────────────────────────────────────────────────────┐
│  叠加栈（OVERLAY_SCOPES：overlay-safe / under-subject │  ← 并列，多轨同时播
│          / anchored / fullscreen）                    │
├──────────────────────────────────────────────────────┤
│  实拍视频                                             │
├──────────────────────────────────────────────────────┤
│  背景链（CARRIER_SCOPES：subject-transform /          │  ← 串联，作用于视频本身
│  footage-transform）                                  │
└──────────────────────────────────────────────────────┘
```

- **载体类**（scale / crop 视频本身）必须**串联**：在同一条 track 上依次对视频做变换，
  由 [carrier.tsx](file:///g:/VideoPipeline/src/remotion/carrier.tsx) 的 `composeCarrierTimeline`
  把多条载体轨合并成绝对时间窗口，避免嵌套 `Sequence` 的时间偏移错误。
- **叠加类****并列**：互不干扰地同时播放。
- **混栈即语义倒置**（把 crop 画在视频上面是荒谬的），校验与渲染双侧都按此分栈。
- 无视频素材（fixture/纯图形模式）时由 [carrier-synth.ts](file:///g:/VideoPipeline/src/remotion/carrier-synth.ts)
  合成影子载体轨（`SHADOW_TRACK_PREFIX`），保证载体语义在无视频时也有确定性产物。

## 6. 调度与门控（schedule.ts）

`src/core/schedule.ts` 实现模板走库决策（而非渲染调度）：

- **两道闸**：先过硬性可用性（门控/确认），再过版式冲突。
- **产路地板**：`custom` 类结果至少抬到 `must_review`，不许静默走库。
- **动态阈值 T**：`T_min=0.50 / T_max=0.80`；样本 `N<8` 退化固定 `T=0.65`；
  期望走库比例锚 `70%–90%`。
- **安全阀**：整批相似度中位数 `< 0.4` → 整批转 custom + 人审（不降阈值硬套库）。
- 校验器侧配合产出 `reviewQueue`（`decision.review === 'must_review'` 的条目清单，
  P2 裁决 2026-10-19），让分级真正产生「该看哪几条」的后果。

## 7. 锚点与烘焙（bake.ts）

模型在 draft.json 里写的是**作者锚点**，烘焙器一次性解析成帧：

```
anchor 语法： "word:37"   第 37 个词
             "cue:12"    第 12 条 cue
             "abs:240"   绝对帧号（无字幕模式下唯一可用）
offset 语法： "-8f"      8 帧（负=抢拍，合法；不得早于锚定词所在 cue 起点）
```

烘焙发生在 storyboard 阶段：`draft.json` → `bake()` → `storyboard.json`（只含帧）+
`bake-report.json`（逐 item 记录解析结果）。锚点字段 `_author` 随即剥离。

## 8. 内置后端与外部命令（可覆盖）

需要模型的阶段都有内置实现，外部命令是可选覆盖（都不配也能跑）：

| 阶段 | 内置实现 | 外部覆盖 |
|------|----------|----------|
| align | whisper.cpp（segment 时间）+ SRT 文字权威 + 内置 DP 对齐（`text-align.ts`） | `ALIGNER_CMD`：占位符 `{wav} {srt} {out} {fps}` |
| perceive | ffmpeg `scdet` 镜头切分 + YuNet 人脸（onnxruntime）+ 几何外扩 + 显著性 | `PERCEIVER_CMD`：占位符 `{video} {frames_dir} {out_dir} {fps} {interval}` |

模型权重不入库（`.gitignore` 忽略 `perceive-models/`），换机需重新下载并校验 sha256。
`PERCEIVE_MODEL` 环境变量可覆盖模型路径。
