## 一、先纠正一个前提：「whisper + SRT 结合」目前只对了一半

`01-align/words.json` 实测结构：

```
顶层键: [cues, fps, words]
cues[i] : {index, text, fromFrame, toFrame, srtFromSec, srtToSec}   ← 句子，SRT 提供
words[i]: {index, word, startFrame, endFrame, confidence}            ← 词，无任何 SRT 时间字段
```

**SRT 只提供句子级时间与文字；词级时间 100% 来自 whisper。**

| 数据 | 谁提供 | 状态 |
|---|---|---|
| 句子时间 | SRT | ✅ 正确 |
| 句子文字 | SRT | ✅ 与原 SRT 逐字 0 差异 |
| **词级时间** | **whisper（独自）** | 🔴 最多漂 −7.06s |

## 二、用户的关键判断成立：SRT 窗口与音频静音天然吻合

### 实测数据

`ffmpeg silencedetect=noise=-40dB:d=0.5` 全片仅 **3 段**静音：

| 段 | 区间 | 时长 | 性质 |
|---|---|---|---|
| 1 | 8.390 – 15.125 | **6.736s** | 大空洞（真静音） |
| 2 | 87.067 – 87.598 | 0.531s | 句中换气 |
| 3 | 96.411 – 96.981 | 0.571s | 句中换气 |

**与 SRT cue 窗口的交叉验证**：

```
【验证1】与 6.74s 大静音重叠的 SRT cue 数: 0← 你手编 SRT 时就留了白
【验证3】静音前一条 cue: [2.650-8.050]就是耐克和Stussy联名的Spiridon Kukini Ⅱ
         静音后一条 cue: [15.133-17.933]它把spirit Donkage的中底和cookie的
         SRT 自身留白: 7.083 s
         实测静音时长 : 6.736 s← 差 0.35s，天然吻合
【验证2】与任意静音段重叠的 SRT cue 数: 2 / 48（均为句中换气，正常）
```

那 2 处重叠经查是**句中换气**，非错位：

```
cue[86.083-88.600] "搭工装裤搭牛仔裤"      与静音重叠 0.531s（静音长 0.53s）
cue[94.283-96.683] "对一双鞋来说真的太省心了"  与静音重叠 0.272s（静音长 0.57s）
```

### 关键发现：文本完全匹配，只有时间错

whisper 塞进 6.74s 静音的 9 个词：

```
它@8.07 把@8.41 spirit@8.74 Donkage@10.69 的@13.00 中@13.31 底@13.65 和@13.96 cookie@14.30
```

**这 9 个词的文本，正是 `[15.133-17.933]` 那条 cue 的内容。**

⇒ **归属判定（哪个词属于哪条 cue）已经 100% 正确；错的只是词落点。**

## 三、结论：联动完全可行，且路子比现有裁决更直接

**方案：用 SRT 窗口作为词的硬边界，词按序填入自己的 cue 窗口；静音段作为客观校验。**

### 为什么这不违反 B2-fix

B2-fix 的原文是「文本源用已有 SRT（**只取文本，不信任其时间戳**）」，
其针对的风险是 **N-6「SRT 与已粗剪拼接视频的时间轴可能偏移」**——
即SRT 可能来自**另一个剪辑版本**，整体错位。

本方案的适用性判断：

| 条件 | 本素材实测 | 结论 |
|---|---|---|
| SRT 是否为用户对**本素材**编辑| ✅ 是（用户原话「那时我已经编辑好拆分的字幕」） | B2-fix 的风险场景不成立 |
| SRT 边界是否与音频静音吻合 | ✅ 差 0.35s | 可作为权威边界 |
| whisper 文本归属是否正确 | ✅ 100% 匹配 | 无需重新分词 |

🔴 **但必须显式校验，不能默认**：若某素材的 SRT 与音频整体错位（对不上静音边界），
则**退回现有行为**（whisper 时间 + 显示层重铺），并报 warning。**判据必须是音频，不是 SRT 自己。**

### 与现有两条 OPEN 裁决的关系

| 裁决 | 现有倾向 | 本方案 |
|---|---|---|
| **M-1d**（门控看不见时间空洞） | 新增 `silentWordRatio`，用 silencedetect 判 | ✅ **完全保留**——它就是校验判据 |
| **M-1e**（whisper 参数改不动漂移） | 「用 silencedetect 约束 DP，禁止词入静音」 | 🔴 **收敛并简化**：不必改 DP，改为按 SRT 窗口直接铺词 |

**即：M-1d = 判据（防回归），本方案 = 修复（消漂移），两者互补而非重复。**

## 四、待你裁决的四点

| # | 问题 | 倾向 | 理由 |
|---|---|---|---|
| **Q1** | 词时是否以 SRT 窗口为准重铺 | **是** | 文本归属已 100% 正确；SRT 边界实测吻合 |
| **Q2** | 是否新增「SRT vs 音频静音」一致性校验 | **是** | 这是 B2-fix 风险的直接兜底；不通过则退回旧行为 |
| **Q3** | 重铺阈值 | 覆盖率 <0.8 才重铺（同`highlightWords`） | 好数据不动，避免把对的改坏 |
| **Q4** | 产物是否回写 | **是**（治本） | 只改显示层是兜底，产物层不修则任何下游读 `words.json` 仍踩坑 |

### 实现落点（若裁决通过）

```
src/stages/builtin-align.ts
  ├─ 1. ffmpeg silencedetect → 静音区间列表（01-align/audio.wav 已在产物里，无需重抽）
  ├─ 2. 逐 cue 算 wordCoverage；<0.8 时按「顺序 + 字数权重」把词重铺进 [srtFromSec, srtToSec]
  ├─ 3. 🔴 一致性校验：SRT 窗口与静音边界不吻合 → 保留原时间 + warning（不静默改坏）
  └─ 4. silentWordRatio 写入 align-report（M-1d 的判据）
```

⚠️ **复用而非复制**：铺词逻辑与 `remotion/caption.ts:227` 的 `highlightWords` 是同一套
⇒ 须上提到 `core/` 供两侧共用（同 `carrier-window.ts` 的先例：同一概念只允许一个真源）。
否则两边算法一旦分叉，报告会对成片说谎。

### 验收标准（可复算）

1. kukini 重跑 align：落进 6.74s 静音的词 **9 → 0**
2. `silentWordRatio` 从 5.9% 降到 ≈0
3. 短停顿（0.53s / 0.57s 换气）**不得**被误判为静音⇒ 需 2–3 条素材验证

5. 全量单测 + typecheck 零输出
