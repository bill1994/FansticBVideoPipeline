## 1. 为什么要做这件事

2026-10-15 的代码现状：10 个模板声明完整，5 个 `overlay-safe` 已有真实组件，219 项测试通过。但调参经验目前只存在于三个地方：memory 日志、代码注释、作者本人记忆。`DUR.enter/exit = 0.18` 这类数值改一次就丢一次来龙去脉；模型挑模板时也看不到每个模板渲出来长什么样。

video-shotcraft 用三个月验证了一条可复制的路径：它的 124 张配方卡不是收集来的，而是从真实成片出发，拆参考片、批量实验、多轮删减、量化验收，再从调校过的实现反向提炼出来的；卡、demo、预览、索引四方一致性由脚本和 CI 强制。我们缺的正是这一层，而我们已有的东西（词级对齐、遮挡契约、不可变快照、219 项测试）它没有。

本计划的目的是把“这次把模板调好看”的一次性劳动，变成下次做新模板时可以直接读取的资产，并让缺件在提交时就暴露，而不是渲完片才发现是占位块。

## 2. 目标与非目标

### 2.1 目标

1. 每个 `core` 模板拥有四件配套资产：配方卡（模型读语义）、三帧静帧（入场/停留/出场）、调校档案（参数为什么是这个值）、真实素材试片记录。
2. 卡、模板声明（`src/templates/builtin.ts`）、组件映射（`src/remotion/templates/index.tsx`）、预览、调校档案五方一致，缺一件或 id 对不上时本地校验直接失败。
3. 参数级决策集中登记，所有 PLACEHOLDER 有追踪状态；改参数先改登记册，再改代码。
4. 模型通过根 `SKILL.md` + 机器可读 manifest + 预览即可选对模板，不需要读组件源码猜效果。
5. 动效模板数量持续扩充，覆盖口播实拍里真实出现的 motion graphic 点位类型；数量增长必须由真实素材的放置需求驱动，并且每个入库动效都过同一道质量工序（§3.2）。初期先把首批 10 个做深，之后按 §8 批次与 §3.4 的扩充策略持续加卡，不设数量上限，但也不为凑数造需求。

### 2.2 非目标（本计划明确不做）

| 不做项 | 原因 |
|---|---|
| 浏览器工作台 / 多轨时间线编辑器 | 操作者是模型不是剪辑师；只读预览足够，工作台投入在一个月以上，见主计划 D3 |
| 以对标数量为目标的冲量式做卡 | 数量要，但每个动效必须来自真实 SRT 点位需求且过 §3.2 工序；video-shotcraft 的 124 卡是三轮砍剩的结果，不是冲量冲出来的 |
| 剪映导出、多平台发布、BGM/SFX 入库 | Python 重依赖与换电脑使用冲突；音频在视觉模板全绿后单独立项（§11） |
| 公开画廊（GitHub Pages） | 第一消费者是本地模型，单文件 HTML 索引足够；公开是以后的事 |
| 逐字复制第三方卡片文字或大段源码 | 允许**参考**开源实现的手法、参数手感、缓动与结构，理解后在本仓库重新实现并纳入自己的库；参考来源逐条登记到 ATTRIBUTION。若确需原样复制代码片段，按 Apache-2.0 要求保留许可头并在文件头标注修改来源，不夹带其硬编码颜色 |
| 新增运行时依赖 | 脚本全部用现有 Node + Remotion CLI 完成；静帧用 `remotion still`，不引 puppeteer |

## 3. 两条工序：成片生产与资产生产

项目里有两条完全不同的工序，读者和触发频率都不同，计划书此前把它们混在了一节，这里分开。

### 3.1 成片生产工序（每条视频走一遍，已存在的五阶段管线）

输入是已经剪辑好的实拍素材和它的 SRT，产物是叠在原片上层的成片。“哪里该放 motion graphic”在第 3 步由模型读 SRT 判断，库里有合适的就选库内模板，没有就写 custom。

```
已剪好的素材 + SRT（00-input）
  → 01-align    音频强制对齐，得到词级时间戳
  → 02-perceive 主体检测与安全区
  → 03-storyboard
       模型读 SRT 文案，逐 cue 判断哪里需要 motion graphic（强调词 / 数据 / 身份条 / 标注…）
       每个点位二选一：
         a. 选库内模板：查 manifest + 配方卡 + 预览，填 params，锚点钉词
         b. 库内无合适形态：写 custom（一次性组件或自定义参数组合），标 decision.routing = custom
  → 04-validate 16 项构建期校验
  → 05-render   动效叠在原片上层出片
  → 06-review   人审放行
```

这条工序不产新资产，它**消费**资产库。它对资产层只有一个要求：模型在第 3 步能快速判断“库里有没有、用哪个”。配方卡、manifest、预览、根 SKILL.md 的选卡段落都是为这一步服务的。

### 3.2 资产生产工序（库里每新增一个动效走一遍，即固定十步）

这是向库里新增一个 motion graphic 模板时的工序，与某一条具体视频无关。触发来源有两个：一批新点位类型在多条素材上反复出现；或某个 custom 动效被复用并证明值得固化（§3.3）。不允许“直接写个组件就标 core”。

```
1. 需求确认   在真实口播素材上找到这个点位（哪类 cue、什么信息需要它），不为凑数造需求
2. 参考拆解   看参考片/开源实现，只记手法、缓动思路、参数手感与来源（ATTRIBUTION），理解后自己重写
3. 组件实现   守既有硬规则：tokens 取色 / frame 纯函数 / paramsSchema / 不新增运行时依赖
4. 注册声明   builtin.ts 声明 + IMPLEMENTED 映射，id 带版本
5. 三帧静帧   remotion still 出入场峰值帧、停留帧、出场帧；另渲一段短视频本地回看
6. 调校留档   问题 → 改动逐条写 notes，必须带帧号与数值，不写“感觉不对”
7. 反提卡片   打开实现源码逐项填配方卡参数表第三列（调大/调小的后果）
8. 派生刷新   跑生成脚本更新 manifest 与预览索引，派生物不手改
9. 真片试片   放进至少一条真实素材：遮挡预算、字幕有效字高 ≥5% 帧高、节奏逐项过
10. 拍板入库  draft → core，结论登记 PARAM-DECISIONS；不达标就留 draft 或 retired
```

参考开源实现时的边界：可以读 video-shotcraft 等项目的 TSX，把它的缓动曲线、时值配比、组件拆分方式学到手，然后在本仓库按自己的契约重新写；它的硬编码颜色、缺 `footprint/paramsSchema` 的组件签名不能直接带进来。参考了哪个文件、用了什么许可，登记在 `library/ATTRIBUTION.md`。

### 3.3 custom 与库的衔接：复用是入库的前置通道

成片工序里产生的 custom 动效默认是一次性的，不自动入库。给它一个明确的晋升路径，避免“每条片都在重写相似的东西”：

| 状态 | 条件 | 位置 |
|---|---|---|
| custom | 第一次出现，只服务当前 cue | storyboard 内联，manifest 不收录 |
| custom-reused | 同一形态在 ≥3 条素材上以 custom 复现，且每次改动很小 | 工作记忆登记“候选动效”，附三次出现的 jobId 与差异 |
| draft | 有人决定固化它，走完 §3.2 第 2-8 步但真片验证不足 | `library/` 中 status=draft，模型选卡范围不含它 |
| core | 走完十步，真片试片通过 | 进 manifest 与根 SKILL.md 选卡范围 |

反过来，core 模板在真实使用中持续不合格，按退役纪律降 draft 或 retired（§8）。

### 3.4 数量怎么扩：按点位类型推进，不按参考库目录抄

扩卡的顺序由口播实拍里真实出现的信息类型决定，优先级参考主计划五批路线，之后按下表持续扩充。每加一类先盘点“custom-reused 里这类出现了几次”，没有真实出现记录的类别不开工。

| 口播点位类型 | 现有覆盖 | 后续扩展示例（需求出现后再做） |
|---|---|---|
| 字幕 | karaoke-word | 双语对照（明确不做，见登记册）、短语高亮、分行强调 |
| 强调文字 | kinetic-line | 逐字弹入、描边大字、关键词放大回收 |
| 身份/标签 | lower-third、tag-float | 多字段身份条、连续标签切换 |
| 数据 | stat-card | 对比数字、进度条、排名变化（数字滚动需先立语义裁决） |
| 指向标注 | pointer-callout（待 perceive） | 区域圈选、放大镜、轨迹箭头 |
| 载体/画面变换 | split-frame、punch-in（待实现） | 画中画、留白构图、B-roll 切入框 |
| 转场 | whip-pan（待确认流程） | 闪白、模糊推移、遮挡划过 |
| 质感层 | noise-grain（待实现） | 暗角、光粒、纸张纹理 |
| 节奏/品牌/声音 | 明确不做（现阶段） | 输入契约落地后再议 |

两个从对标项目学到、本计划照抄其精神的纪律：

1. **参数真相只有一份，在实现源码里**。卡片只写语义、典型值与“调大调小的后果”，不抄第二份具体数字；改实现后重新生成派生资产。
2. **删和加同等重要**。video-shotcraft 两次大筛选分别砍掉 209 中的 161 个、216 中的 66 个。模板达不到可发布水平时回退为 draft 或 retired，不用占位块冒充完成。

## 5. 三类资产的内容契约

### 5.1 配方卡（`library/cards/**/*.md`）

一卡一文件，路径按 family 分目录。frontmatter 给脚本读，正文给模型读。卡片**不写坐标、不写颜色、不写帧数**——这三条是项目既有硬规则，卡片层同样遵守。

```markdown
---
id: caption/karaoke-word@1.0
family: caption
subtype: karaoke-word
status: core                # core / draft / retired，只有 core 进根 SKILL.md 选卡范围
dependsPerceive: false      # 是否依赖 02-perceive 产物
preview: previews/posters/caption-karaoke-word-hold.png
---

## 适用
口播字幕带，需要逐词跟随人声的场景；复杂背景可开底框。

## 意图
为什么有这个模板、解决什么观感问题。

## 动效核心
只写语义与结构（逐词高亮、进出场方向），具体缓动/时值引用实现文件，不抄数字。

## 参数表
| 参数 | 典型值 | 调节手感与越界后果 |
|------|--------|--------------------|
| boxed | false | 复杂背景下开 true 提可读性；相邻 cue 连续加框会显碎 |

第三列是这张卡的核心价值：写“调大/调小会怎样”，不写合法区间（合法区间由 paramsSchema 管）。

## 已知坑
命门参数与历史回踩记录，每条注明是哪轮调校发现的（链接 polish 档案）。

## 音频关系
字级高亮误差实测（中位 / P95）；误差不达标时降级为短语高亮的条件。

## 参考实现
src/remotion/templates/karaoke-word.tsx —— 参数真相以此文件为准。

## 调校档案
polish/final-notes/caption-karaoke-word.json
```

### 5.2 manifest（`library/manifest.json`，脚本派生）

合并模板声明与卡片 frontmatter，供根 SKILL.md、`build-library-page.mts`、未来的模型选卡步骤共同读取。人不手改这个文件。

```json
{
  "schemaVersion": "1.0",
  "generatedAt": "由脚本写入，不手改",
  "templates": [
    {
      "id": "caption/karaoke-word@1.0",
      "family": "caption",
      "subtype": "karaoke-word",
      "status": "core",
      "scope": "overlay-safe",
      "layer": 90,
      "dependsPerceive": false,
      "implemented": true,
      "card": "cards/caption/karaoke-word.md",
      "posters": {
        "enter": "previews/posters/caption-karaoke-word-enter.png",
        "hold": "previews/posters/caption-karaoke-word-hold.png",
        "exit": "previews/posters/caption-karaoke-word-exit.png"
      },
      "params": [
        { "name": "boxed", "type": "boolean", "required": false, "safeToEdit": true }
      ],
      "finalNote": "polish/final-notes/caption-karaoke-word.json"
    }
  ]
}
```

`safeToEdit` 借自 video-shotcraft 工作台的三层可编辑度：文案、`boxed` 这类标 true；缓动、时值、footprint、颜色一律 false（命门参数不开放）。当前没有 UI，这个字段先作为文档与未来边界的事实源。

### 5.3 调校档案（`polish/notes/*.json` 与 `polish/final-notes/*.json`）

每轮调校一个文件，定稿后把终版复制为 `final-notes/<family>-<subtype>.json`。每条问题必须带帧号或数值，不允许“感觉慢/不好看”这类无法回放的描述。

```json
{
  "stem": "caption-karaoke-word",
  "round": 2,
  "date": "2026-10-xx",
  "sample": "jobs/<jobId>（真实素材标识，不入库）",
  "issues": [
    "第 180-196 帧：高亮切词比人声晚约 2 帧，连续读词时高亮滞后明显"
  ],
  "changes": [
    "高亮进度插值提前 2f；enter 由 x 位移改为透明度+裁切，避免与逐词高亮抢注意力"
  ],
  "verification": {
    "method": "三帧对照 + 真片回看",
    "result": "滞后消失；与同句字幕并放出框不超过 1 次"
  }
}
```

`PARAM-DECISIONS.md` 是参数级决策总册，一条参数一节，字段固定：参数名 / 当前值 / 状态（已定 / 待校准）/ 实测依据（带样本与分布）/ 越界后果 / 首次落档日期。首批先登记已有结论的 `MATCH_MIN_SIMILARITY = 0.35`（正确匹配 0.655–1.000、半句听漏 0.455、错位 ≤0.154），再把四个 PLACEHOLDER（`meanConfidenceMin`、`alignedRatioMin`、`maxItemsPerCue`、`DUR.enter/exit`）以“待校准”状态占位。改代码前先改这本册子。

## 6. 单模板资产化流程（§3.2 十步的展开表）

这张表是资产生产工序的操作版，每往库里加一个动效照走一遍；成片生产工序（§3.1）不走这张表。

| 步 | 动作 | 产物 | 停住条件 |
|---|---|---|---|
| 1 | 在真实口播素材上确认需求（哪个 cue 需要这类信息） | 需求一句话写进卡片“适用” | 为凑数做模板 → 不做 |
| 2 | 看参考片与开源实现，手法/缓动/参数手感记入卡片，来源登记 `ATTRIBUTION.md` | 来源条目 + 手法笔记 | 逐字搬运对方素材/整文件 → 改为理解后重写；确需复制代码片段则保留许可头、文件头标注来源与修改 |
| 3 | 写组件：tokens 取色、frame 由 props 传入、interpolate 全 clamp、不引新依赖 | `src/remotion/templates/<id>.tsx` | 需写死颜色/坐标/帧数才能实现 → 回到设计；参考实现里的硬编码色值一律换成命名令牌 |
| 4 | 注册声明与映射：`builtin.ts` + `IMPLEMENTED` 表 + `paramsSchema` | 两处源码改动 | 映射 id 拼错会被 `assertRenderMapValid` 拦 |
| 5 | 渲三帧静帧与一段短视频，肉眼确认入场/停留/出场 | posters 三张 PNG | 出场缺失或与入场无差异（已有回归测试，人工再过一遍） |
| 6 | 调校并留档：问题与改动逐条写 notes，带帧号数值 | `notes/<stem>-rN.json` | 只剩“感觉不对”说不出帧号 → 继续看到能说出为止 |
| 7 | 打开实现源码反提卡片参数表第三列 | 配方卡定稿 | 卡片与实现参数对不上 → 以实现为准修卡 |
| 8 | 跑生成脚本：manifest、poster 引用、index.html | 派生物刷新 | verify 报漂移 → 提交派生物或修源头 |
| 9 | 真实素材试片：遮挡预算、字幕有效字高 ≥5% 帧高（借 Q11）、节奏 | final-note 的 verification | 有一项不过 → 回第 6 步 |
| 10 | 状态由 draft 改 core，登记册记录拍板 | 卡片 frontmatter + PARAM-DECISIONS | 不达标但想保留 → 留 draft，不进模型选卡范围 |

## 7. 工具脚本与校验门禁

四个脚本均为 Node + 现有依赖，放在 `tools/`，与现有 `render-probe.mts`、`setup-whisper.mts` 同风格（`node --experimental-strip-types` 可直接跑）。

### 7.1 `gen-library-manifest.mts`

- 输入：`src/templates/builtin.ts` 的声明（用现有 `BUILTIN_TEMPLATES` 导出，不重新解析源码）、`library/cards/**/*.md` 的 frontmatter、`src/remotion/templates/index.tsx` 的 `listImplemented()`。
- 输出：`library/manifest.json`（键排序，与现有 `writeJson` 风格一致）。
- 行为：卡片缺失时该模板 `card` 字段为 null 并在终端列出；frontmatter 的 id 与声明 id 不一致时报错退出。

### 7.2 `render-previews.mts`

- 由现有 `tools/render-probe.mts` 演进：当前探针已能逐帧 SSR 输出 HTML，本脚本改为调 `remotion still` 出真实浏览器像素。
- 每个 core 模板固定出三帧：入场峰值帧、停留中段帧、出场帧；帧数从模板的 DUR 常量计算，不手算。
- 产物落到 `library/previews/posters/`；`--clip` 选项另渲完整短视频到 `previews/clips/`（不入库）。
- 无真实视频也能跑：沿用现有 demo props 的 `hasVideo: false` 占位底。

### 7.3 `build-library-page.mts`

- 读 `manifest.json` + posters，生成单文件 `library/index.html`：每模板一格，展示三帧、适用语义、参数表、状态徽标。
- 不引前端框架、不引网络资源，纯静态，双击可开。它替代工作台，服务两个读者：作者自己选模板、模型截图读图。

### 7.4 `verify-library.mts`

五方一致性校验，任何一项不通过即退出码非 0：

1. `builtin.ts` 每个声明在 manifest 有条目且字段同源；
2. core 模板必须同时具备：卡片、组件映射、三张 poster、一份 final-note；draft 模板只要求卡片；
3. manifest 重新生成后与磁盘版本逐字节一致（防手改派生物）；
4. 卡片 frontmatter id 与文件路径、声明 id 三者逐字相同；
5. `paramsSchema` 每个键在卡片参数表中有对应行，卡片不得出现 schema 之外的参数。

### 7.5 本地总校验与 CI

`package.json` 新增：

```json
"library:gen": "tsx tools/gen-library-manifest.mts && tsx tools/render-previews.mts && tsx tools/build-library-page.mts",
"library:verify": "tsx tools/verify-library.mts",
"verify": "tsc --noEmit && vitest run && tsx tools/verify-library.mts"
```

`verify` 先只做不依赖 Remotion 二进制的检查；demo 三阶段端到端（修掉现有 draft 里两处 `highlightColor` 漂移后）并入 `verify`，作为主计划 P0 的一部分，不在本计划内重复施工。

GitHub Actions 等本机能稳定跑通后再加，两个作业即可：`npm ci && npm run verify`；core 模板 `remotion still` 首帧不崩。不追求对标项目四作业的规模。

## 10. 多 agent 并行时的边界（BRIEF 模板）

第 2 周起若派多个 agent 并行调校，开工前写一页 BRIEF，固定四段，避免风格发散（对标项目 150 个镜头并行改版靠的就是这份约束）：

1. 背景：这批模板服务什么口播场景、参考片给人什么观感；
2. 能动：缓动曲线、时值、进出场方向、排版层级、文案（只用虚构占位）；
3. 不能动：组件 props 签名、tokens 取色、footprint 语义、禁 `Date.now`/`Math.random`/CSS animation、不新增依赖；
4. 统一工具：共用缓动表与 DUR 常量放在哪、poster 帧号怎么算、notes 写到哪个目录。

## 11. 音频资产（后置项，仅预留口子）

视觉模板全部 core 之前不启动。启动时规模按口播场景定 20-30 个：字幕轻入、强调 whoosh、数字提示、转场四类。沿用对标项目的 audition 工序：批量下载 → 校验哈希去重 → 逐个试听 → 留用项登记时长、ffmpeg 实测峰值、建议钉点与授权 URL。两条口播特有约束先记下：音效锚点钉在人声词点间隙，不压字；BGM 只铺底并做响度预算。届时另立子计划，本目录结构里预留 `library/audio/` 位置即可，本周不建空目录。
