### 1.3 我们已有的优势（优化中必须守住）

| 优势 | 证据 | 守住什么 |
|---|---|---|
| **内容与音轨严格对齐** | M-1 方案 b + `text-align.ts` DP + `alignedRatio` 门控；实测 8/8 cue、72 词、0 空洞/重叠/倒序 | 这是 video-shotcraft **完全没有的能力**，是核心壁垒 |
| **可自动断言的质量属性** | 183 项测试 + 16 项校验，空洞/重叠/单调性/首末帧全锁 | 优化不得放松这些断言 |

## 2. 优化方向

> 每个方向按「现状问题 → 优化目标 → 具体措施 → 预期收益」四段式。
> 维度取舍：原要求中「性能与稳定性」在本项目**不是独立瓶颈**（素材 30s 级、非高并发），
> 因此与「功能完善」合并为 **D1**，只保留有限目标。新增 **D6「决策与知识资产」**，
> 因为调研发现这是本项目最被低估的缺口。

### D1 · 功能完善与产出价值（最高优先）

**现状问题**
- 10 个模板**契约完整、实现为零**（`builtin.ts` 声明 vs `MotionItem.tsx` 占位块）
- `templates/` 目录只有 `.gitkeep`
- 渲染管线能跑通，但产出对所有模板**完全相同**

**优化目标**
- 至少 **5 个模板有真实 Remotion 实现**，渲染结果**肉眼可辨互不相同**
- 每条模板附一份**「调校过的实现 + 参数手感表」**（借鉴 1 的完整双层结构）
- 端到端产出一条成片
- 🔴 **修订（C3）**：成片要达到**用户可自行发布**的质量 —— 不是"能看就行"
- ⚠️ **修订（C1）**：**移除批处理/并发/吞吐相关目标** —— 每周几条不构成性能瓶颈

**具体措施（🔴 修订为"两轮走"，因 C3 提高验收线）**

> 但 C3（自己发布）意味着**最简形式不能作为终点**。
> 所以拆成两轮：**第一轮证明管线**，**第二轮打磨到可发布**。两轮的判据不同。

| 轮次 | 步骤 | 内容 |
|---|---|---|
| **第一轮**（近期） | 1.1 | ✅ **已定**（2026-10-14）：`caption/karaoke-word`、`typography/kinetic-line`、`typography/lower-third`、`typography/tag-float`、`data/stat-card` —— 5 个 **overlay-safe**，排除 `annotation/pointer-callout`（依赖 perceive）。详见 §4.4 |

| | 1.3 | 每个实现**必须**满足：只读 `useCurrentFrame()`、`interpolate` 全程 `clamp`、禁 CSS animation/transition |
| | 1.4 | 补测试：**各模板渲染输出结构必须两两不同**（防"又一个灰框"回归） |
| | 1.5 | 端到端渲一条完整成片，**肉眼确认"动起来了"** |
| | 1.6 | 🔴 **契约字段审计**（对应问题 9）：逐个字段查"有没有消费者"。零消费的两种处置：<br>· 若**设计上承重但实现漏了**（如 `occludesSubject`）→ 补实现，或在文档中明确标注"待 perceive 分支落地"<br>· 若**确实不需要**（如 `handoffIn`，`handoffTo` 在 track 层已有）→ **删除**，不留死字段 |

| | 1.8 | 用真素材（非 demo）验证一次，产出**一件可发布的成片** |

**预期收益**
- 🔴 解除"产出无价值"这一**唯一致命问题**
- 前面所有工作（对齐、校验）**第一次有可见产出**
- 参数手感表让后续调参**可积累**，而非每次重调

**关键指标**：`模板实现数 ≥5`、`模板渲染去重后数量 = 模板总数`（防灰框回归）、`端到端成片可播`、**`用真素材产出 1 件可发布成片`**

### D3b · 从 video-shotcraft 借鉴的边界（用户问"能不能直接套"）

**结论：❌ 不能直接套代码，✅ 可以借鉴实现手法。**

三条不能直接套的硬原因（均有源码证据）：

| # | 原因 | 证据 |
|---|---|---|
| 1 | **契约层不匹配** | 它的组件签名是 `{ text, duration, bottom }`（`Caption.tsx`），**没有** `footprint` / `layer` / `paramsSchema` / `scope` / `minVisibleInFrames` —— 而这是我们模板契约的必需项 |
| 2 | 🔴 **颜色硬编码** | `Caption.tsx` 里 `const AMBER = 'oklch(52% 0.115 65)'`、`color: 'oklch(45% 0.006 82)'` **写死在组件内**；`DigitRoll.tsx` 默认参数 `color = 'oklch(52% 0.115 65)'` 同。**直接违反我们的 P1「禁硬编码颜色」+ Spec 附录 A「禁写颜色 / CSS」** |
| 3 | **形态不对** | 它的 `Caption` 是"整句淡入淡出的信息条"（22px mono / 全大写 / 字距 0.14em），**不是逐词高亮**。我们的 `caption/karaoke-word` 要消费 SRT 逐词数据做**逐词高亮** —— 它没有这个功能 |

**真正可借鉴的**：

| 我们的模板 | 它的对应 | 可用程度 |
|---|---|---|
| `data/stat-card` | `assets/lib/DigitRoll.tsx` | ✅ **高** —— 里程表式逐位滚动，实现干净（只读 `useCurrentFrame`、`interpolate` 全程 `clamp`，**符合我们的确定性红线**），只需把硬编码色改为**命名令牌** |
| `typography/kinetic-line` | `demos/typography/lead-word-zoom-assemble/`、`type-entrance-moves/` | ✅ 中 —— 借缓动曲线与时值配比 |
| `typography/tag-float` | `demos/typography/pill-slot-cycle/` | ✅ 中 —— 同上 |
| `typography/lower-third` | 无直接对应 | ❌ 需自行实现 |
| `caption/karaoke-word` | 无对应（它的 Caption 不是逐词） | ❌ 需自行实现，**且这是最重要的一个** |

**许可义务（Apache-2.0，可商用）**：若复制/修改其代码，必须
① 保留版权声明（`Copyright 2026 Wei Yihao`）；
② **修改过的文件带显著修改声明**（"You must cause any modified files to carry prominent notices"）。

2. 🔴 **两个模板卡在别的依赖上**：
   `carrier/split-frame` 是 **D4 tier2 退让的载体**（强依赖 D4 先立裁决）；

**分批路线图**（保证"最后全都有"）：

| 批次 | 模板 | 时点 | 为什么是这个时点 |
|---|---|---|---|
| **第 1 批** | 5 个 `overlay-safe` | 近期 | 无任何依赖，同一栈，可立即开工 |
| **第 2 批** | `ambience/noise-grain` + `cinematic/punch-in` | 中期 | **不依赖 perceive / D4**，只需背景链与 fullscreen 能力就位（`noise-grain` 是剩下 5 个里最简单的，`occludesSubject: false`） |

> **结论**：**不是"不做"，是"分 5 批做"**。第 1、2 批不依赖任何外部条件；
> 第 3、4 批分别搭 D4 与 perceive 的车。全部落地的时点 = 长期阶段结束。
