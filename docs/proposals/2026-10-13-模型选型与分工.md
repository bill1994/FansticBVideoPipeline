## 0. 一句话结论

**「重不重」不是问题，「测量 vs 选择」才是分界。**

- **测量**（逐词时间戳、包围盒坐标、显著性峰值）→ 交给专用小模型，误差比容差小一个数量级
- **选择**（候选框三选一、shot 分类、挑模板写文案）→ 交给多模态大模型，这正是它的强项
- 「用多模态大模型兜」这个方向**成立**，但要兜在**选择层**，不是测量层

顺带纠正：`align` / `perceive` 需要的不是「重型模型」——whisper.cpp 与 MediaPipe 都是**几十 MB 到百 MB 级、CPU 可跑**的东西。

## 2. 分界原则：测量 vs 选择

| | 测量 | 选择 |
|---|---|---|
| 典型任务 | 逐词时间戳、bbox 坐标、显著性峰值区 | 候选框三选一、shot 是不是 B-roll、挑模板、写文案 |
| 输出形态 | **连续数值 / 精确坐标** | **离散判断** |
| 容差 | 极小（见下表） | 无严格数值容差，判断对就行 |
| 谁来做 | 专用小模型（检测/对齐） | 多模态大模型 |
| 多模态模型的实测表现 | 误差比容差**大一个数量级** | 稳定、便宜（全片仅 20–60 次调用） |

### 误差 vs 容差（决定性的一栏）

| 任务 | 我们的容差 | VLM 实测误差 | 差距 |
|------|-----------|-------------|------|
| 词级时间戳 | ±1 帧 = **±33ms**（30fps） | 通常几百 ms 量级，或接口干脆不给 | 一个数量级以上 |
| bbox → 遮挡比例 | 人脸 0%、B-roll ≤30% → 坐标误差须 **< 2–3%** | grounding 偏差 **20–40%**；前沿 VLM grounding IoU 仅 **0.09–0.13** | 一个数量级 |
| 显著性峰值区 | 连续数值 | 不是语言任务 | — |

### 为什么是架构性的，不是提示词问题

VLM 的视觉编码器把像素变成**语义 patch token**，为了语义相似度优化，**丢掉了精确位置关系**。它输出「物体在 30% 处」是在**预测下一个 token**，不是在**测量**。

有实测为证：有人做过五轮补救 —— 直接提示 → 加边缘标尺 → 烧进密集网格 → 换 Claude / GPT-4V / Moondream → 多轮裁剪 —— **全部失败，偏差 20–40%**，小模型干脆整图给一个框。另一项审计里，前沿 VLM 在 grounding 任务上 IoU 只有 0.09–0.13，且**模型倾向于给出过大的框**。

还有一个杀死确定性的因素：**Qwen2.5-VL 的 grounding 准确率随提示措辞在 15%–82% 之间摆**。我们整条链是「帧是真相」的确定性烘焙，报告要能进 git diff —— 这种敏感度不能接受。

## 3. align —— 核实到的事实与一个反转

### 核心事实

| 项 | 结论 |
|----|------|
| 官方路径 | **`@remotion/install-whisper-cpp`** —— Remotion 官方包，装 whisper.cpp + GGML 模型 |
| 输入 | 16kHz mono WAV（whisper.cpp 硬要求） |
| 产出 | `tokenLevelTimestamps: true`（内部走 `--dtw`）→ **逐词时间戳 + probability** |
| 模型体积 | tiny / base / small / medium / large-v3-turbo，**75MB ~ 1.5GB** |
| 性能 | 8.5 分钟视频，base.en 约 85 秒（有 GPU 加速）；CPU 也能跑 |
| 依赖 | 不需要 Python。Windows 走预编译二进制，Unix 走 make |

⇒ **正好就是 C2-2 门控要的「每词置信度」**，且完全留在 Node/Remotion 生态里。

### 反转：DeepSeek V4.1 的音频编码器**就是 Whisper-Large-v4**

所以「用 DeepSeek 兜 align」**不是另一条技术路线**——它跑的就是 Whisper。差别不在模型，在**接口**：

| | whisper.cpp（本地） | 多模态聊天接口 |
|---|---|---|
| 输出 | 逐词时间戳 + probability | **纯文本** |
| C2-2 门控能用吗 | ✅ | ❌ 拿不到每词置信度 |
| 后处理改写 | 无 | 会在转写之上「润色」，把听不清的脑补成通顺句子 |

第二条坑更隐蔽：我们的锚点是 `word:37`，必须与 SRT 文本对得上。**一润色，锚点与音频就错位了，而且错得看不出来** —— 正是 C2-5 列为「看起来是对的」那类最危险的错误。

### ⚠️ 但这里有个真实的语义问题（需要裁决）

whisper 是 **ASR（自己听写）**，而 B2-fix 要的是**强制对齐**（拿 SRT 文本当准绳、只推时间）。whisper 听出的词与 SRT 未必逐字一致。三条路见 §6 的 **M-1**。

## 4. perceive —— 这里才是真需要检测，但也不需要「重型」

### 小模型清单（几 MB 级，CPU 可跑）

| 模型 | 体积 | 用途 |
|------|------|------|
| `pose_landmarker` (Lite) | 5.8 MB | 主体 bbox + 关键点 |
| `pose_landmarker` (Full) | 9.4 MB | 同上，精度更高 |
| `hand_landmarker` | 7.8 MB | 手持物（D5） |
| `face_detector` (BlazeFace) | 230 KB | 人脸区（D2 人脸 0% 预算） |
| `image_segmenter` (Selfie) | 250 KB | 主体分割 |
| `object_detector` (EfficientDet-Lite0) | 7.3 MB | 通用目标 |

B-roll 的「shot 级显著性峰值区」可用经典谱残差法，**零模型**。

### 运行时有个取舍（需要裁决）

- **MediaPipe Python**：`pip install mediapipe` 一行，最省事 —— 代价是项目里多一个 Python 小工具
- **全 Node**：MediaPipe 的 JS 版主要面向浏览器，纯 Node 要配 canvas 垫片；或走 `onnxruntime-node`
  —— 保持单一运行时，代价是多写一层适配

见 §6 的 **M-2**。**这正是当初把 perceive 做成 `PERCEIVER_CMD` 适配器的原因**：把选型留给使用方，而不是替他钉死。

## 5. VLM 兜底的正确形态

### 先测量，再让模型选

1. 检测器给出 **2–3 个候选框**
2. 把候选框**画在截图上**，与原图一起交给多模态大模型
3. 问：「哪个是讲解主体？」「这个 shot 是 B-roll 吗？」

**这是选择题，不是填空题** —— 全片只 20–60 个 shot，**20–60 次调用**。
这正好可以把 **F6 的「人工兜底」换成模型兜底**。

### 确定性怎么保住

F3 的 `confirmed.json` 记录的本来就是「**某人**在**某时**确认了**什么**」。把人工换成 VLM，要求从「逐字节可复现」降到「**决策可追溯**」—— 这是个真正成立的降级。

**但有一个硬前提**：

> 结果必须**写进 `06-review/confirmed.json`，不能每次重新问**。

否则 storyboard 每跑一次都不一样，「帧是真相」的烘焙链就废了。
即：**VLM 当一次性的决策者，决策结果落盘 → 确定性保住。**

### 8.1 `01-align` 产物契约已改（M-1 / M-1c，2026-10-13）

原表把 `01-align` 契约判为「不需要改」，**依据是「换模型不动下游」**。
但 M-1 裁决取方案 **b**（文本权威归 SRT）之后，这条不再成立 ——
**换对齐模型会改变产物里「谁是权威」这个事实**，不落盘就无法审计：

| 字段 | 状态 | 说明 |
|------|------|------|
| `textSource: 'srt' \| 'whisper-asr'` | **新增必填**（M-1c） | 文本权威来源，可审计。**缺它，一份 `words.json` 无法自证它是 SRT 权威还是 whisper 权威** —— 而这正是 M-1 的争点本身 |
| `alignedRatio: number` | **新增必填 + 新增门控项**（M-1c） | SRT 词成功对上 token 的比例 0–1 |
| `alignedRatioMin`（`thresholds`） | 🔴 **PLACEHOLDER `0.8`** | 门控阈值。**须与 `meanConfidenceMin` 一并校准，不得分开拍** |

**为什么 `alignedRatio` 不可省**：`meanConfidence` 衡量的是「**whisper 对自己听到的词有多自信**」，
它**测不到「SRT 与音频是否对得上」**。一个 whisper 自信但与 SRT 完全不符的场景会
**直接通过门控** —— 这违反项目 P0「绝不伪造结果」：
**一份对不上的 `words.json` 比一次显式失败危险得多。**

> 完整契约见 Spec §5.1.1 / §4.6；门控阈值校准状态见 README「待实测的数值」。
