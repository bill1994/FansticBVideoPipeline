## 2. 已核实的确定事实

以下均为读代码/实测所得，非推测：

1. **渲染层的载体机制不缺**。`carrier.tsx` 已把 `[trackStart, trackEnd]` 切成 item 段与间隙段，任一时刻只渲染一份 children、只应用零或一层变换。**tier2 落地不需要动渲染架构**。
2. **`punch-in` 已经"包裹视频"**：它不画自己的内容，只把 children 放进 `scale` 容器透传（`src/remotion/templates/punch-in.tsx`）。这是载体类的正确形态样板。
3. **`split-frame` 的 `paramsSchema` 只有一个键**：`{ inset: 'number' }`，无值域、无语义说明。
4. **载体类模板的 `footprint` 语义是"视频的位置"**，不是 overlay 的位置 —— 源码注释：`/** 载体类：作用于实拍视频本身（背景链，串联）。 */`
5. **"载体区"这个概念在代码与 SPEC 中均无定义**（全仓 grep 无命中）。
6. **同 track 内载体 item 重叠的语义未定义**，当前实现取 first-wins 并在段数据标 `overlapped: true`（`carrier.tsx` 文件头）。
7. **W-D2-02 已撤回**：其判据「`footprint ⊇ safeArea`」因上述第 3、4 条而不成立 —— 对分屏可能误报、对放大完全漏报。

## 3. Q1 · 承载字段：载体退让的结果记在哪

### 选项 A：`StoryboardItem` 新增可选字段

```ts
carrier?: { template: string; params: Record<string, unknown> };
```

- **改谁**：`types.ts` 的 `StoryboardItem`；validate 写入；`carrier.tsx` 读取
- **优点**：与 item 一一对应，天然逐 item；不改 storyboard 结构（不插新轨道）；渲染层已有分段机制可直接消费
- **缺点**：一个 item 同时承载"overlay 内容"与"视频变换"两件事，语义稍重；需扩 `paramsSchema` 校验（#16）覆盖这个嵌套结构
- **风险**：`carrier` 若与 `motion` 指向的模板 scope 冲突（如 overlay-safe 的 item 又挂 carrier），需明确禁止规则

### 选项 B：validate 往 storyboard 插入新 track / item

- **改谁**：validate 产出"改写后的 storyboard"（当前它只就地改 footprint，不增删结构）
- **优点**：语义最干净 —— 视频变换本就该是背景链上的一条独立 item，与 overlay 解耦
- **缺点**：**validate 从"就地改值"变成"改结构"**，是能力边界的实质扩张；需要定义"谁拥有插入后的 storyboard"（落盘由 render 负责，见现有 `W-D2-01` 的备注）；插入位置/轨道顺序需规则
- **风险**：与"校验器是纯函数、逐项独立判定"的性质张力最大 —— 插入顺序会影响报告内容

### 选项 C：塞进 `item.params`

- **优点**：零契约改动
- **缺点**：`params` 是**模板自己的参数**（由 `paramsSchema` 声明与校验）。把"载体选择"塞进去会让模板语义污染成"模板 + 布局引擎"，且 #16 会把它当普通参数校验
- **风险**：直接违背 P1 裁决的初衷（那次正是因为 `params` 混入非模板语义的 `text` 才立的规矩）

### 权衡对照

| 维度 | A 新字段 | B 插新 item | C 塞 params |
|---|---|---|---|
| 改动面 | 小（1 个类型 + 3 处读写） | 大（validate 能力扩张） | 最小 |
| 逐 item 几何 | ✅ 天然 | ✅ 天然 | ⚠️ 与模板参数混居 |
| 语义清晰度 | 中 | **高** | 低 |
| 与现有纪律冲突 | 无 | 与"纯函数、逐项独立"张力 | **与 P1 冲突** |

## 4. Q2 · 键粒度：映射按什么索引

### 现状

```ts
export const CARRIER_FALLBACK: Record<string, string> = {}; // motion id → carrier template id
export function carrierFallbackFor(motion: string): string | undefined
```

### 选项 A：按 motion 索引（现状）

- 一个 motion 全局对应一个载体
- **缺点**：放不下逐 item 几何（代码注释已指出）；同一 motion 在人脸镜头与 B-roll 镜头下可能该退到不同位置

### 选项 B：按 `motion × regionKind` 索引

```ts
CARRIER_FALLBACK: Record<`${motion}|${RegionKind}`, string>
```

- **优点**：能区分 face（0% 额度，必须退）/ broll（30% 额度，可能不必退）；键仍是静态配置，可审计
- **缺点**：配置量 ×3；仍不含几何

### 选项 C：逐 item 显式声明（配合 Q1 选项 A）

- 不查全局表，由模型/人工在 item 上直接声明 `carrier`（或由 validate 在冲突时写入）
- **优点**：几何天然逐 item；无全局表的"一处配置污染全片"问题
- **缺点**：模型要理解"何时该声明载体"，与"不让模型手算布局"的倾向有张力；若无冲突也应允许声明（片头主动分屏）

> 注意：选项 A/B/C **不与 Q1 一一绑定**。例如 Q1 选 A（字段）+ Q2 选 B（按 regionKind 查默认值、写入时落成具体值）是可行组合。

## 5. Q3 · 载体模板语义：`split-frame` 怎么变画面

`paramsSchema: { inset: 'number' }`，其余全无定义。**"载体区"在文档中无定义**（见 §2.5）。需要先确定下面三件事：

### 5.1 待定义的三件事

1. **视频往哪缩**：左 / 右 / 上 / 下 / 居中留边？
2. **缩多少**：`inset` 是「边距占画面比例」还是「视频缩小后的宽度比例」？值域？
3. **overlay 放哪**：空出来的区域是 overlay 的可行域吗？由谁计算？

### 选项 A：缩放（视频整体缩进一侧，内容完整可见）

- 例：`inset=0.5` → 视频等比缩到右半屏 `[0.5,0,0.5,1]`，左半屏空出
- **优点**：**主体永不丢失**（内容全在框内），对 `face` 这类 0% 额度的通道最安全；实现简单（transform + scale）
- **缺点**：视频变小，主体也变小 —— 产品细节可能看不清；画面观感是"画中画"
- **对 W-D2-02 的影响**：变换后可证明"全部内容仍可见"，正确的安全区判据应恒为通过

### 选项 B：裁剪（只保留一侧，另一侧被切掉）

- 例：`inset=0.5` → 只显示视频右半边，左半边丢弃
- **优点**：视频不缩小，主体保持原有清晰度
- **缺点**：**主体可能被切出画外** —— 正是 D4 要解决的那类问题，用裁剪解决遮挡会引入新问题
- **对 W-D2-02 的影响**：需要按裁剪窗口判断主体是否仍可见，这才是 W-D2-02 真正的用武之地

### 选项 C：双边分屏（视频占一半，另一半是纯色/图形区）

- 与 A 的差别在于"空出来的区域画什么"：A 是空白/背景，C 是设计过的图形区
- **优点**：成片观感更像"设计过的版式"而非"缩小的视频"
- **缺点**：多一套图形区模板要设计

### 5.2 无论选哪个都必须补的接口

```ts
/** 变换执行后，原画面里哪些区域仍然可见（归一化，相对原画面）。 */
visibleRegion(params: Record<string, unknown>): Footprint | null;
// null = 全画面可见（无裁切）
```

- `punch-in`（scale s）：可见区域 = 以中心为基准的 `1/s` 区域
- `split-frame`（缩放）：返回 `null`（全可见）
- `split-frame`（裁剪）：返回保留的那一半

**这个接口是 W-D2-02 正确判据的唯一依赖** —— 有了它，撤回的那条校验才能以正确形式重立。

## 6. 与 W-D2-02 的关系

`D2-2`（2026-10-17）当日增补又撤回，原因见该条 `REVERTED` 说明。撤回的核心结论：

> `footprint` 表达的是**视频位置**（载体类），而裁切量由**变换参数**决定
> ⇒ 用 `footprint ⊇ safeArea` 判断"主体是否被切走"，**两头都不成立**。

**正确判据（待 Q3 定案后实施）**：

```
对每个 carrier 类 item:
  vr = template.visibleRegion(item.params)   // null = 全可见
  if (vr === null) continue                  // 无裁切，跳过
  if (!shot.safeArea ∩ vr 完全包含)          // 主体被裁切到画外
    → warning
```

即：判据的输入从 `item.footprint` 改为 `visibleRegion(params)`。
