## 0. 一句话目标

构建一套**「接近全自动」**的 Remotion motion-graphic overlay 工作流：

- **输入**：一段已拍摄、已粗剪拼接、**无任何文字和特效**的视频，以及对应的 **SRT 字幕文件**
- **流程**：模型看画面+文案 → 产出 storyboard（含 motion idea）→ 人审阅修改 → 自动产出 Remotion 项目 → Remotion Studio 预览迭代 → 渲染导出
- **输出**：一个**可运行的完整 Remotion 项目**

### 三条硬约束（用户原始需求）
1. Motion graphic 出现时**不得遮挡主体**（presenter / 讲解主体）
2. 可对主体进行 **scale / crop**，并置入特定 graphic 载体
3. 动画可**持续交叉**，不必一段对应一个 motion；支持**多轨 timeline 并行**；一段 motion 可持续覆盖多段话；各种 motion 穿插组合成一个整体

## 2. 阈值策略（两道闸串联）

**两道闸，串联不并列：**

- **闸1 路由**：`sim_max ≥ T` → template 产路 / custom 产路。（决定"走哪条产路"）
- **闸2 审核强度**：按 `confidence` 只调制"人工介入强度"（auto 落地 / 挂备选 / 必审），**不改变产路**。

> 串联的意义：避免同一模糊点被**双重惩罚**。闸2 不许回头改产路。

**动态阈值**：`T = clamp( 间隙锚 , 约束于 配额锚分位 )`

- **配额锚** = 期望走库比例区间（建议 **70%–90%**）
- **间隙锚** = 分数排序后的最大间隙（elbow）
- **硬边界** `T_min = 0.50` / `T_max = 0.80`（用户原提的 50/80 降级为**边界**，不当取值）
- **安全阀**：整批 `sim_max` 中位数 < 0.4 → 判"库不适配"，**整批转 custom + 人审**，禁止降阈值硬套库
- **样本少**（单条/数据不足）→ 退化固定 `T = 0.65`

**schema 决策字段**：每条 idea 存 `sim_max` / `confidence` / `routing: template|custom` / `review: auto|alternatives|must_review`

> 重要澄清：B4 里的"95% 走库"是**方针修辞**，**不是阈值参数**。

## 3. 模板库结构（双轴 + 命名空间版本化）

**轴 A｜功能族（family，可无限扩的命名空间，12 类）**

`caption`（字幕/词级卡拉OK，**必备**）/ `typography` / `data` / `annotation` / `carrier` / `brand` / `ambience` / `cinematic`（影像处理，**有实拍故强相关**）/ `transition` / `rhythm` / `sfx` / `custom`

**轴 B｜作用域（scope，枚举，固定）**

`under-subject` / `overlay-safe` / `anchored` / `subject-transform` / `footage-transform` / `fullscreen`

**每模板强制契约**

`scope · layer · occludesSubject · paramsSchema · status(core|experimental|custom)`

**可扩机制**

- 命名空间：`family/subtype@version`（如 `typography/lower-third@1.2`）
- 版本锁定 → 升级不破坏旧 storyboard

## 4. 时间轴模型（进行中）

### C1 轨道模型（已决，含修订）
- **`layer`（z 序，整数）** 与 **`track`（作者分组/时间线）** 拆开
- 同一 layer 可容**多条 track**；**轨内 items 允许重叠**（表达同层并行元素，如两段文字同时进）
- z 由 `layer` 决定；同 layer 内按**声明序**（后者在上），必要时给可选 `zIndex`
- **互斥按需声明** `exclusive: "<组名>"`（如 lower-third），默认不互斥
  - 代价：互斥不再由结构保证 → 需在校验期/运行时查同 exclusive 组冲突
- track 保留价值：分组可读（HTML 编辑器一列）、挂 track 级属性（如"跟随主体 X"）、接力分组
- **Remotion 映射天然对齐**：重叠 = `<Sequence>` 可重叠；z = DOM 嵌套/渲染顺序

```json
{
  "tracks": [
    { "id": "typo-a", "layer": 60, "items": [ { "span": "L2→L3", "motion": "typography/kinetic-line" } ] },
    { "id": "typo-b", "layer": 60, "items": [ { "span": "L2.5→L4", "motion": "typography/tag-float" } ] }
  ]
}
```

### C2 时间坐标（已决）
- **真相层 = 帧**：`storyboard.json` 最终落盘 `{ fromFrame, durationInFrames }`
- **作者语法层 = cue 锚点 + 帧偏移**：模型写 `{ "anchor": "cue:12", "offset": "-8f" }`（**不让模型手算帧**）
- **一次性烘焙**：resolver 在生成时把锚点解析成帧并落盘，锚点用完即弃
- **不设 `guard` 文本快照**（重剪罕见 → 砍掉防错位机制）
- 编辑页**双显示**：`帧 372 ｜ = cue:12 +0`
- **锚点粒度**：cue 级为主 + 词级可选（词级来自 Whisper 逐词时间戳）
- **`abs`**（绝对帧/秒）作为手写逃生口

## 5. 外部调研结论（同类 agent skill + Remotion 生态）

### 5.1 关键判断
主流 MG 分类（16/10 类）是"**从零做一条 MG 视频**"的分类，**对"在实拍上叠 overlay"基本不适用**。
真正对标的先例 = **Remotion 自己的模板生态**（RVE 81 模板分 7 类）。

### 5.2 五个同类仓库

| 仓库 | 作用 | 许可 |
|------|------|------|
| `github.com/Finderchangchang/brewreel` | storyboard.json → Remotion（最接近本项目） | Apache-2.0 |
| `github.com/Vincentwei1021/video-shotcraft` | 157 镜头卡 + workbench | Apache-2.0 |
| `github.com/aeonfun/aeon` | agent 框架（schema 未公开） | — |
| `github.com/GroMarketing/remotion-qa` | 渲染后 QA | MIT |
| `github.com/oo-pibe/audio-bed-check` | BS.1770 音频 QC | MIT |

### 5.3 八个可直接抄的机制
1. **模型只填表不写代码**：只挑镜头 + 填文字，禁写坐标/帧数/颜色/CSS
2. **三档校验器 `validate.mjs`**：errors 必改 / warnings 尽量改 / human 列出交人；有 ✗ 不出片
3. **语义化退出码**：0 可交付 / 1 校验没过 / 2 参数错 / 3 版式✗ / 4 渲染失败 / 5 排队超时 / 6 内部错误 / 130 中断
4. **`revise.mjs` 一句话修改 + `meta.tweak` 旋钮**：改一处不重写整份；受限 op；最多 3 轮；改前备份；改完先校验
5. **custom 镜头围墙**：文字/数字只能经 slots 传入；静态检查拒硬编码；渲染前 tsc；安全区溢出/空白帧/冷冻动效归因到镜头；渲染锁下运行
6. **分段渲染 `lock.json`**：改哪页渲哪页，没改的复用（治渲染成本）
7. **确定性红线**：禁 `Date.now()`/`Math.random()`；伪随机固定种子（mulberry32/哈希，seed 从 index 派生）；helpers 有 vitest 单测
8. **渲染后测量，不信 composition 数字**（remotion-qa 核心洞察）

### 5.4 关键参照物
- **镜头卡体系**：157 卡 / 214 样片 / **10 大类** = `camera, data, effects, interaction, opening, outro, rhythm, transition, typography, ui-entrance`。每卡含 Purpose/energy/建议时长/参数/实现说明/**已知坑**；**卡给语义，demo 源码才是参数真相**；"已知坑参数不得降档"
- **workbench**：Vite + React + zustand + @remotion/player；成片交付后按 镜头/转场/字幕/音效 拆多轨可视化编辑；契约 `src/workbench.ts` → **即 phase 3+4 的现成方案**
- **ClipCard**：把外部 mp4 包成可被运镜骨架驱动的"卡片主角"，含 OffthreadVideo 交叉淡化循环（素材短于镜头时无缝续播）→ **需求 2 的现成组件**
- **remotion-qa 规则**：dead air = 静态段 − 所需阅读时间（最长行字符/15 + 0.4s×额外行 + 1s）；safe-zone 平台 inset 数值表；最小字号 floor（on-device pt = canvas px/3）。**safezone 机制可挪用作"主体安全区"检测**
- **声音即时间轴**：先合成旁白 → 拿逐字时间 → 倒推镜头时长（0.15 + 旁白 + 0.35）
- **卡拍**：librosa 网格拟合 BPM/相位 + 鼓点三分类；时间线写 `beatF(n)`；渲后回测切点误差 ≤3f；整画面级节拍冲击全片 ≤3 处

### 5.5 根本差异（勿照搬）
这些 skill 都是 **"从零做一条视频"**（纯图形/截图/AI 画面）；本项目是 **"在实拍上叠 overlay"**。
- 它们的 layout / 主题 token 体系 **不可照搬**
- 它们的通用骨架（schema / 三档校验 / revise / 确定性 / 渲染后测量 / 卡点 / workbench / 分段渲染）**可抄**
- **"不遮挡主体"这块它们没有，必须自建**（可借 remotion-qa 的 safezone 算法骨架）
